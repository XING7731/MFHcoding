# 智能安全帽 · 微信小程序监控端

把 **STM32 智能安全帽** 上报到 **巴法云** 的数据，在微信小程序上实时显示，
并且可以**在线调整报警门限** —— 既可以下发到设备（设备按新门限驱动蜂鸣器），
也可以**只存本机**（只让小程序告警，完全不碰板子）。

> 最近的改动（2026-09-18）：新增「阈值设置」页（温湿度 / 心率 / 血氧 / 气体的门限
> 在线下发 + cv 指纹回读确认），湿度此前没有判据、这次补上；首页新增**阈值预警横幅**。
> 详见固件工程 `docs/34`。
>
> 最近的改动（2026-09-23）：阈值设置页新增 **「仅存本机（只让小程序告警）」**，
> 并加了"门限还没保存"提示 —— 此前"保存门限"和"下发设备"被绑在同一个按钮上，
> 想只让小程序告警的用户无路可走。告警判据本来就在小程序侧，与设备门限无关。
> 详见固件工程 `docs/40`。

## 1. 数据链路（上行双通道 + 下行复用同一条链路）

```
                                          ┌─ WSS 实时推送  wss://bemfa.com:9504/wss
STM32 安全帽 ──MQTT(10s/条)──▶ 巴法云主题 ─┤   （socket 合法域名）
  心率/血氧/温湿度/气体/姿态/报警          └─ HTTP 轮询   apis.bemfa.com/va/getmsg
                                             （request 合法域名）

小程序 ──HTTPS──▶ apis.bemfa.com/va/sendMessage?topic=<主题>/set
                  （与取数同一主机、同一份白名单）
       └──▶ 巴法云把消息推给所有订阅了 <主题> 的设备 ──▶ 设备换用新门限
```

**下行没有新建任何东西**：设备上报时已经订阅了该主题（`MQTT_SUBSCRIBE_ENABLE`），
平台的 `/set` 推送正好落在它已订阅的主题上，于是落进 ESP01S 的 AT 接收缓冲，
由固件的 `net_poll_config()` 认出 `"cfg":1` 标记后提交。

> ⚠️ **不能直发裸主题**：云端取数接口只给"该主题最新一条"，直发会把设备刚上报的
> 遥测顶掉，实时页立刻变成过期数据。所以一律发 `<主题>/set`
> （官方文档：`/set` = 推送给订阅该主题的设备且不推给发布者自己）。

**为什么要两条上行通道？**

小程序没有裸 TCP socket，连不上 `bemfa.com:9501`。它能用的只有两类 HTTPS/WSS 接口，
而这两类在微信公众平台里是**两个互相独立的配置项**（request 合法域名 / socket 合法域名）：

| 通道 | 地址 | 需要配哪一栏 | 特点 |
|---|---|---|---|
| WSS 实时推送 | `wss://bemfa.com:9504/wss` | **socket 合法域名** | 板子一发就到，实时；无需轮询 |
| HTTP 轮询 | `https://apis.bemfa.com/va/getmsg` | **request 合法域名** | 5 秒取一次最新记录 |

只配其中一栏时，另一条必然失败 —— 这正是「我配了合法域名还是取不到数」最常见的成因。
所以两条都实现了，**任意一条通就能用**；默认 `自动` 模式优先用推送，连不上自动退回轮询。

## 2. 快速开始（3 步）

### 第 1 步：导入工程
微信开发者工具 → 导入项目 → 选择本目录 → AppID 用你自己的（当前配置的是 `wxc49ee42eb1a117b2`）。

### 第 2 步：⚠️ 配置服务器域名（**真机运行必做，否则一定失败**）

微信公众平台 → **开发管理 → 开发设置 → 服务器域名**，里面是**两栏**，都要填：

| 栏位 | 填什么 |
|---|---|
| **request 合法域名** | `https://apis.bemfa.com` |
| **socket 合法域名** | `wss://bemfa.com` |

> **⚠️ 一个字符的坑**：注意是 **`apis`**.bemfa.com（**带 s**）。
> 巴法云官方的小程序教程里写的是 `https://api.bemfa.com`，少一个 `s` ——
> 白名单不认子域，两者完全不能互相顶替。而且实测 `api.bemfa.com` 上
> **并没有可用的取数接口**（各种路径都返回业务错误，`/va/getmsg` 直接 404），
> 所以按官方教程那一条配，是**一定取不到数**的。
> （验证脚本：`tools/wxmp_host_probe.py` / `wxmp_host_probe2.py`）
>
> 另外：socket 合法域名只写主机名，**不带路径和端口**（就是 `wss://bemfa.com`，不是 `.../wss`）。
> 域名必须配在**上面那个 AppID 的账号**下 —— 页面「连接设置」里会显示当前 AppID，可直接核对。
> 只配了一栏也能用：把通道手动切成对应的那一个即可。

**开发者工具**里可以临时绕过 request 校验：详情 → 本地设置 → 勾选「不校验合法域名…」。
但 **socket 域名在工具里同样会被校验**，所以工具内测试推送时也要配好。

> 小提示：`project.private.config.json` 是开发者工具自己生成的，它的优先级
> **高于** `project.config.json`。本工程预设的 `urlCheck: false` 会被它覆盖成 `true`，
> 以工具里「本地设置」勾选框的实际状态为准。

### 第 3 步：核对连接参数
打开小程序，页面底部「连接设置」里确认两项与固件 `user_config.h` 一致：

| 项 | 默认值 | 固件里对应 |
|---|---|---|
| 巴法云私钥 UID | `d2f5cf22…`（32 位） | `BEMFA_UID` |
| 主题名 | `temp001` | `BEMFA_TOPIC` |

板子上电联网后，页面上就会开始出现数据。

## 3. 页面说明

### 3.1 实时监测（首页）

| 区块 | 内容 |
|---|---|
| 顶部横幅 | **只在设备上报了非正常状态时出现**（红色=摔倒/气体/SOS，橙色=心率异常等） |
| **阈值预警横幅** | **按你保存的门限二次判读**，列出越限的项。它和上面那条不是一回事：上面来自设备上报的 `st` 字段（固件自己的判定，蜂鸣器也由它驱动），这条是小程序侧的判读 —— 标题里标了「· 小程序判定」。只出现这一条、没有上面那条，可能是门限刚改还没下发到设备，**也可能是你本来就想只让小程序告警**（见 3.3「仅存本机」） |
| 状态条 | 设备在线 / 数据延迟 / 已离线 + 数据时刻 |
| **通道标签** | 当前走 WSS 推送还是 HTTP 轮询、健不健康、降级原因 |
| 生命体征 | 心率 HR、血氧 SpO₂（未佩戴时显示 `--`，不是 0；**为什么没数会分四种说法，见 5.3**） |
| 环境监测 | 温度、湿度、气体 MQ-2，各自带门限判读（光照于 2026-09-22 整条删除） |
| 姿态检测 | 合加速度 \|a\| 与姿态判定（摔倒判据门限 1.8g）、三轴加速度 |
| 设备与链路 | 取数通道、报文序号 seq、**PPG 状态**、运行时长、设备本地时间、轮询统计、**门限配置（cv 指纹是否与本机一致）** |
| 门限提示 | 把"接近或超过门限"的项单独列出来，并写明判定用的是你保存的门限 |
| 连接设置 | 通道选择、私钥 / 主题 / 轮询间隔，两个域名的复制按钮，AppID 核对 |

**门限判读用的是「你在阈值设置页保存的那一套」**，不是写死在代码里的常量 ——
这样"界面说的"和"蜂鸣器做的"不会各说各话。只有撞击一项例外（见 3.3）。

**「一键连接诊断」**：取数失败时自动触发，也可手动点。它会对**两条通道各发一次真实尝试**，
把结果逐行列出来（AppID / HTTP 地址 / HTTP 结果 / WSS 地址 / WSS 结果），
直接告诉你卡在哪一层、该去配哪一栏。

### 3.2 趋势与记录

- **趋势折线图**：7 个视图可切换 —— **温湿度（双 Y 轴同屏）**、温度、湿度、气体、
  心率、血氧、合加速度。画在 `<canvas type="2d">` 上，绘图计划由 `utils/chart.js`
  算出（**不依赖任何 npm 图表库**，与 `mqttws.js` 同一个取向）。
- **图怎么读**：
  - 折线遇到**没测到的点会断开** —— 断开的意思是"这一刻没测到"，而不是 0。
    心率/血氧未佩戴时就是这个样子。
  - 前后都缺测的**孤点**会画成一个圆点，不会被丢掉。
  - 温湿度同屏时 **左轴看温度、右轴看湿度**（右轴刻度数字的颜色＝湿度那根线的颜色，
    否则不知道该读哪边）。
  - 单指标图上那条**橙色虚线是报警门限**。它取的是**你在「阈值设置」里保存的那一套**
    （和设备侧生效的门限可能还差一次下发 —— 到实时监测页底部看 cv 指纹就知道同步没有）。
    撞击那条线取的是固件编译期常量（这一项不可在线配置）。
    门限离当前数据很远时它**不会出现** —— 为了让它露脸而把纵轴拉长，曲线会被压成一条平线，
    得不偿失。
  - 每个指标下方仍有文字统计（最新 / 最高 / 最低 / 平均 + 有效值个数）：
    canvas 万一没画出来，这些数仍然可读。
- **报警记录**：只记录设备上报了**真实告警状态**的时刻（`normal` 不记流水），避免刷屏。

> 这两块的数据来自**小程序本机缓存**：巴法云的 HTTP 接口只提供"最新一条"，
> 不提供历史查询（实测 `num=10` 返回 `data:null`）。所以趋势只在"打开过小程序的
> 那段时间"内有效，缓存上限 **240 个点（约 40 分钟）** / 100 条报警记录。
> 240 点约占 26KB 存储，远低于单个 key 1MB 的上限。

### 3.3 阈值设置

**第三个 tab。** 门限以前是固件 `user_config.h` 里的编译期宏，改一个数要重新编译烧录；
现在在这里改完点一下，设备在线生效。

| 区块 | 内容 |
|---|---|
| 当前读数 | 每 30 秒取一次最新报文，把实时的温度/湿度/心率/血氧/气体摆在对应滑块**上方** —— 可以看着实时值定门限 |
| 指纹核对 | 本机门限的 cv vs 设备回读的 cv。三态：**已生效**（两值相等）/ **两边不同**（还没下发、或被拒、设备重启回默认、**或你用了「仅存本机」**）/ **设备不支持回读**（老固件） |
| 门限分组 | 温度（高/低）、湿度（高/低）、心率（上/下限）、血氧（下限）、气体 —— 每组：滑块 + 加减按钮 + 「按当前读数填」 |
| 蜂鸣器 | 开关。**只管数值越限**（温湿度/心率/血氧/气体）；摔倒报警、SOS、网络失败不受它影响（安全功能不能静音） |
| 迟滞 | 列出五个迟滞量，并说明"越过门限置位、回落到 门限−迟滞 才解除" |
| 下发 | 主题（可复制）、报文预览（可复制、带字节数）、量程速查表、校验问题列表、「保存并下发设备」「仅存本机」「恢复默认值」、下发结果 |

**可在线改的量与量程**（越界会被固件**整条拒绝**，界面上会先拦下来并说明原因）：

| 字段 | 含义 | 量程 | 出厂默认 |
|---|---|---|---|
| `tHi` | 高温门限 | -20 ~ 60 ℃ | 40 |
| `tLo` | 低温门限 | -20 ~ 60 ℃ | 10 |
| `hHi` | 高湿门限 | 0 ~ 100 %RH | 90 |
| `hLo` | 低湿门限 | 0 ~ 100 %RH | 20 |
| `gas` | 气体报警门限 | 1 ~ 100 | 50 |
| `hrLo` / `hrHi` | 心率下/上限 | 20 ~ 200 bpm | 50 / 120 |
| `sp` | 血氧下限 | 50 ~ 100 % | 90 |
| `buz` | 越限蜂鸣开关 | 0 / 1 | 1 |

**不在**这个范围内的一项及原因：撞击（属于摔倒判据，刻意不给小程序改）。
（光照原先也不在这一范围内，2026-09-22 已随功能整体删除，见固件工程 `docs/39`。）

**门限存在哪**：本机 `wx.setStorageSync`（这份 = **实时监测页判读用的门限**）；
设备存在 **RAM** 里，掉电回出厂默认 —— 不写 Flash 是因为擦页会停总线 20~40ms，
而 5ms 周期的撞击监视任务是摔倒判据的采样源，不值得为"掉电保存"冒漏报风险。
所以设备重启后指纹会显示"两边不同"，想同步点一下「保存并下发设备」即可。

**改门限是两步，别漏第二步**：拖滑块 / 点加减按钮**只改这张界面**，
必须点一次按钮才落本机。没落本机时实时监测页不会按新门限判读 ——
这一页顶部会有一条橙色提示「门限还没保存」告诉你。

**两个按钮，区别只在"碰不碰板子"**（2026-09-23 新增，见固件工程 `docs/40`）：

| 按钮 | 本机存储 | 发请求给设备 | 用在哪 |
|---|---|---|---|
| **仅存本机（只让小程序告警）** | ✅ 立刻写 | ❌ **一条都不发** | 只想让小程序报，不想动板子 |
| **保存并下发设备** | ✅ 推送成功后写 | ✅ 发到 `<主题>/set` | 要让板子蜂鸣器也按新门限响 |

★ 前者的价值是：**告警判据本来就在小程序侧**（`bemfa.checkThresholds` 读本机存储），
和设备门限完全独立。所以"只让小程序告警"这件事不需要改固件、也不需要发任何请求。

**只有推送成功才落本机**：用「保存并下发设备」时，推送失败本机那份**不变**。否则本机判读
会永久性地与设备不一致（首页说超了 25℃，设备按 40℃ 在跑）。
（「仅存本机」不发请求，所以不存在这个问题。）

### 3.4 演示：让蜂鸣器现在就响

现场 26℃ 时 40℃ 的高温门限永远触发不了，所以：

1. 进「阈值设置」，看温度那行右边的 `当前 26.4 ℃`；
2. 把**高温门限**滑到比它低一点（如 25℃），或点那行的「按当前读数填」再减一格；
3. 点「保存并下发设备」；
4. 等 ≤10 秒：蜂鸣器按 1.5 秒/次鸣响，OLED 显示 `TEMP HIGH`，
   首页出现**阈值预警横幅**，设备信息里「门限配置」变成与本机一致；
5. 演示完点「恢复默认值」再下发一次，或直接断电重启。

### 3.5 演示：只让小程序告警（板子一声不响）

同一个门限，换成点另一个按钮即可：

1. 同样把高温门限滑到 25℃；
2. 点 **「仅存本机（只让小程序告警）」**；
3. 首页立刻出现**阈值预警横幅**（显示温度越限），而**板子不响** ——
   全程没有一条请求发给设备；
4. 页面上「门限配置」会显示"两边不同"，并提示这可能是你有意为之，不是故障；
5. 想让板子也跟着响时，再点「保存并下发设备」补一次。

## 4. 数据字段对照（固件紧凑报文）

固件为绕开巴法云"记录字段 191 字节"的上限，用的是紧凑键名，典型报文约 161 字节
（2026-09-18 起多了 `cv`，约 11 字节；2026-09-22 删掉 `lux`，少约 5 字节）：

```json
{"ts":"10:02:28","seq":14,"hr":null,"spo2":null,"t":26.4,"h":58.0,
 "gas":21,"ax":3.9,"ay":0.2,"az":0.6,"st":"normal","up":148245,"tsv":0,
 "cv":38972}
```

| 字段 | 含义 | 小程序里显示为 |
|---|---|---|
| `ts` | 设备本地时间 `HH:MM:SS` | 设备本地时间（**未校时，仅供参照**） |
| `tsv` | 时间戳是否可信（1/0） | 时间戳状态 |
| `seq` | 报文序号，自增 | 报文序号 seq（判新旧的唯一依据） |
| `hr` | 心率 bpm，`null`=未测到 | 心率（`--`） |
| `spo2` | 血氧 %，`null`=未测到 | 血氧（`--`） |
| `sc` | 血氧是否已标定（0 估算 / 1 已标定） | 血氧后面的 `~`（估算值才带） |
| `ps` | **PPG 测量状态**：0 没手指 / 1 稳定中 / 2 采集中 / 3 测量完成 | 设备与链路 → **PPG 状态**；也决定心率 `--` 时的那句说明（见 5.3） |
| `t` | 温度 ℃ | 温度 |
| `h` | 湿度 %RH | 湿度 |
| `gas` | MQ-2 气体相对量 0~100 | 气体 MQ-2 |
| `ax`/`ay`/`az` | 三轴加速度 g | 三轴加速度；\|a\| 由三轴算出 |
| `st` | 状态文案 | 报警横幅 / 当前状态 |
| `up` | 设备运行时长 ms | 运行时长（格式化为 `天 时:分:秒`） |
| `cv` | **设备当前生效门限的指纹**（16 位） | 设备与链路 → 门限配置 |

`st` 的全部取值（对应固件 `alarm_text_ascii()`）：`normal`、`FALL ALARM`、
`GAS ALARM`、`SOS ALARM`、`HR ABNORMAL`、`SPO2 LOW`、`TEMP HIGH`、`TEMP LOW`、
`WIFI FAIL`、`SENSOR ERR`、`unknown`。
（原先还有 `LOW LIGHT`，2026-09-22 随光照功能删除，见固件工程 `docs/39`。）

## 5. 判定规则（都在 `utils/bemfa.js` 里，可自行调整）

### 5.1 在线 / 离线 —— 用**最近一次真的收到新数据**的时刻

板子没有 VBAT 纽扣电池，RTC 每次上电都回到编译初值，报文里的 `ts` 会和真实时间差好几天，
所以不能用 `ts`。但也不能用"请求成功"当在线判据：

> **HTTP 请求成功 ≠ 设备在线**。板子停机后，平台接口照样返回那条老记录，
> 请求一路 200 —— 只看请求成功，界面会永远显示"在线"。
> （这一条有专门的测试用例守着：`wxmp_page_test.js` 第 4 组）

正确做法是**把在线判据绑在 `seq` 变化上**：

| 距最近一次新 seq | 判定 |
|---|---|
| ≤ 30 秒 | 🟢 设备在线 |
| 31 ~ 90 秒 | 🟠 数据延迟 N 秒 |
| > 90 秒 | 🔴 设备已离线（显示离线时长） |

| 通道 | 基准怎么来 |
|---|---|
| WSS 推送 | 收到推送＝设备此刻活着，用本机当前时间 |
| HTTP 轮询 | 用平台给的云端接收时间 `unix`（记录是老的会直接反映成"离线"） |

另外有个 3 秒的心跳定时器专门刷新这个状态 —— 推送模式下设备停掉后不再有数据到达，
没有它界面会一直停在最后一条的"在线"上。

### 5.2 门限提示（用的是**你在阈值设置页保存的门限**）

`checkThresholds()` 返回 `{key, text}` 数组（`key` 供 wxml 当 `wx:key`，
也让"这条提示对应哪个量"可被程序判断）。

| 项 | 门限 | 来源 |
|---|---|---|
| 气体 | > `gas` | **本机保存**（出厂 `GAS_ALARM_LEVEL` = 50） |
| 温度 | > `tHi` 高温 / < `tLo` 低温 | **本机保存**（出厂 40 / 10℃） |
| 湿度 | > `hHi` 高湿 / < `hLo` 低湿 | **本机保存**（出厂 90 / 20 %RH，本轮新增判据） |
| 心率 | < `hrLo` 或 > `hrHi` | **本机保存**（出厂 50 / 120 bpm） |
| 血氧 | < `sp` | **本机保存**（出厂 90%） |
| 合加速度 | > 1.8g | 编译期 `FALL_ACCEL_HIGH_G`（**不可在线配置**） |

> ⚠️ 这一栏的数值曾经写错（撞击停在旧的 2.5g，光照门限也用错了口径），
> 2026-09-18 更正。它们在 `tools/wxmp_thresh_test.js` 第 1 节里被**逐项对着固件头文件**
> 断言 —— 这类"镜像常量"抄错不会有任何报错，只会表现成"设备在响、小程序说正常"。
>
> 撞击门限不可在线配置的理由：它是**摔倒判据的一部分**，属于安全功能，刻意不给小程序改。
> （光照那一条已于 2026-09-22 整条删除，见固件工程 `docs/39`。）

判读用的是本机保存的门限，而**设备侧的蜂鸣器按设备上生效的门限动作**。
两边不一致时以设备侧为准 —— 到「阈值设置」重新下发即可对齐，
实时监测页底部的「门限配置（cv）」会明说同步没同步。

这些提示**只是前端二次提醒**，不替代固件自己的报警逻辑。

### 5.3 心率 / 血氧为什么没读数 —— 四种情况，四句话

心率**不是持续测量**，而是**一次测量**：贴手 → 稳定 3 秒 → 采集 10 秒 → 出结果并冻结。
所以下面四种情况的 `hr` 都显示 `--`，但该做的事完全不同。区分靠报文里的 `ps`：

| `ps` | 设备状态 | 小程序会说什么 | 你该做什么 |
|---|---|---|---|
| 0 | 没接触到皮肤 | 把指腹贴住光学窗口… | 戴好 / 贴好传感器 |
| 1 | 稳定中（3 秒） | 已检测到接触，正在稳定 | **等着**（此时 `--` 是正常的） |
| 2 | 采集中（10 秒） | 正在采集 10 秒窗口，保持不动 | **等着**，别动 |
| 3 | 测量完成但没测出 | 本次测量已跑完，但没采到有效脉搏 | **拿开手，重贴再测一次** |
| （无） | 老固件不带 `ps` | 未检测到（未佩戴 / 信号不足） | 升级固件就能看到上面四种 |

> ⚠️ `ps=3` + `hr=--` 是**最容易误判**的一格：设备明明测完了，只是没采到有效脉搏。
> 2026-09-21 之前小程序把它显示成"未佩戴"，会让人跑去查佩戴 —— 方向指错。
> 现在它标成橙色并明说要重测。这条有断言守着：
> `wxmp_bemfa_test.js` 第 5b 节（"`ps=3` 的文案里不能出现『未佩戴』"）。
>
> 测不出本身**不一定是故障**：算法在信号不够好时会**明确不给结果**，而不是给一个
> 随机数（这是刻意的取舍，见固件 `docs/31`、`docs/35`）。连续几次都不出，
> 才需要去看 OLED 第 2 行的 `PPG d:.. a:..` 排查硬件与手法。

## 6. 已知限制与注意事项

1. **只能看最新一条**：平台接口不给历史，趋势靠本机缓存。
2. **设备时间不可信**：见 5.1，判新旧一律看 `seq`。
3. **心率/血氧常为 `null`**：需要佩戴到位；`--` 表示"没测到信号"，不是"心率是 0"。
4. **姿态读数要会看**：静止平放时 `|a|` 应≈1.0g。若长期远大于 1g
   （例如一直显示 3.9g），那是 MPU6050 量程换算/零偏的问题，不代表一直在撞击 —— 详见固件工程 `docs/21`、`docs/22`。
5. **同私钥连接**：WSS 通道用私钥作 ClientID。已实测（`tools/wxmp_wss_test.js` 含互踢探测）
   小程序连接期间板子仍持续上报，两者可共存。但**别用 MQTTX / 网页控制台以同一私钥登录**，
   那类客户端仍可能把板子顶下线。
6. **轮询别设太小**：板子 10 秒一条，轮询设 2~5 秒足够；设 1 秒只会重复取同一条。
7. **WSS 手写实现**：`utils/mqttws.js` 是不依赖 npm 的极简 MQTT 3.1.1 客户端
   （只用到 CONNECT / SUBSCRIBE / PINGREQ / PUBLISH 四种报文）。这么做是为了免掉
   "构建 npm"这一步；代价是协议层要自己维护，改动时请跑 `wxmp_wss_test.js`。

## 7. 排错对照

> **编译期就报错、根本进不了页面？** 直接看 §10 —— 那种情况和本节无关。

| 页面现象 | 原因 | 怎么做 |
|---|---|---|
| `域名未加入 request 合法域名白名单` | 没配 request 栏，或配成了 `api.bemfa.com` | 加 `https://apis.bemfa.com`（注意带 s） |
| `socket 合法域名未配置` | 没配 socket 栏 | 加 `wss://bemfa.com`；或把通道切到 HTTP |
| 通道显示「HTTP 轮询（已降级）」 | WSS 连不上，已自动退回轮询 | 功能不受影响；想用推送就去配 socket 栏 |
| `该主题下还没有任何消息` | 板子没上报过 / 主题名不对 | 查板子 OLED 第 8 行是否 `NET: OK`，核对主题名 |
| `平台返回 code=…` | 私钥或主题错误 | 核对 32 位私钥与主题名 |
| `报文不是合法 JSON` | 主题里混入了别的东西（例如自己用 MQTTX 发的测试报文） | 用板子的真实主题，或清掉测试数据 |
| 显示"设备已离线"但板子在跑 | ① 上报周期被改长 ② 热点/网络问题 ③ 平台记录被丢弃（报文 >191 字节） | 看首页 seq 是否在涨；确认固件是紧凑报文版本 |
| 心率一直是 `--` | **先分清是哪一种**：四种情况的 `hr` 都是 `--`（见 5.3） | 看首页「PPG 状态」那行：`未检测到手指`=去戴好；`稳定中`/`采集中`=**等着**（此时没数是正常的）；`测量已完成`=**拿开手重贴重测**。重试多次仍不出，才看 OLED 第 2 行的 `PPG d:.. a:..` |
| 趋势图一直是空的 | 只在收到**新 seq** 时才记点 | 确认首页 seq 在变化；至少要有 1 个点 |
| 趋势图上有断口 | 那段时间没测到（心率/血氧最常见） | **这是对的，不是 bug**：断开＝这一刻没测到，不是 0 |
| 图上没有那条橙色门限虚线 | 门限离当前数据太远，出于可读性不画 | 想知道门限有没有越界，看首页的「门限提示」 |
| 换了指标线却不动 | canvas 是异步取的节点，偶发取不到 | 下拉刷新一次；仍不动就看 `page.lastPlan`（排错用） |
| **下发门限后设备没反应** | ① 设备离线 ② 报文被固件整条拒绝 ③ 设备重启回默认 | 看首页「门限配置」的 cv：**两边不同**就是设备那份还没生效，点「保存并下发设备」重发；若一直不同，检查是不是**高低门限颠倒**或超了量程（页面会先拦下来并说明） |
| **调了阈值但首页不报警** | 大概率是**没点保存按钮** | 滑块只改界面。这一页顶部出现橙色「门限还没保存」就是这个情况 —— 点「仅存本机」或「保存并下发设备」任意一个 |
| **心率/血氧从来不报警** | 报文里 `hr`/`spo2` 是 `null`，**无读数不做判** | 看首页生命体征是否显示 `--`。这不是门限的问题，是 PPG 没测出（固件工程 `docs/35`/`38`）。有读数之后门限立刻生效 |
| **点「保存并下发设备」没反应** | 门限组合被本地校验拦住了 | 页面上会有一块红框列出具体哪一项不对，按提示改 |
| **推送成功但设备仍是旧门限** | 设备没收到，或收到了但被拒 | cv 会显示**两边不同**。设备 RAM 掉电回默认，重启后要重新下发 |
| **首页说"阈值预警"但设备不响** | 本机保存的门限与设备上生效的不是同一套 | 正是 cv 要解决的问题：去「阈值设置」重新下发，直到显示"已生效" |
| 拿不准到底卡在哪 | —— | 点「一键连接诊断」，两条通道各测一次并逐行报告 |

## 10. 工具报「编译错误」怎么办

**先别改代码。** 这类报错有两条完全不同的来路，长得却很像：

| 报错长这样 | 病因 | 处理 |
|---|---|---|
| 指向一个**已被删除**的文件、或 `ENOENT ...` | 工具的编译缓存陈旧 | 清缓存（见下） |
| 说某页面/组件找不到，**但文件确实在** | 同上 | 同上 |
| 标签不配对、JSON 非法、用了被禁语法 | **真·代码问题** | 按提示修 |

**怎么区分**：把报错里提到的那条路径**拿去文件夹里找**。
**找不到 ⇒ 一定是工具的问题** —— 因为它在描述一个磁盘上已不存在的状态。

### 一键自查

桌面上的 **`小程序工程预检.bat`**（双击即跑，也可把工程文件夹拖上去）：

1. 独立复现微信编译期的全部硬性检查（7 组 23 项，**不依赖开发者工具**）
2. **把开发者工具日志里最近报的错原文捞出来**，并逐条标注那个文件是否还在磁盘上

工具的界面只给你一句"编译错误"，真正的 `ENOENT xxx` 只在日志里 ——
这个脚本就是去把那句话捞出来。

### 清缓存（按顺序试，第一步通常就够）

1. 菜单「**工具 → 清缓存 → 清除全部缓存**」→ 重新编译
2. 还不行：「**项目 → 关闭项目**」再重新打开
   （只清缓存不重启时，工具内存里的编译实例可能仍是旧的）
3. 还不行：工程挪到**不含空格**的路径下重新导入
   （当前 `WeChat smart helmet` 含空格，该路径上工具的文件监听容易失效）

> 根因与完整证据链见固件工程 `docs/24-小程序编译错误排查.md`。
