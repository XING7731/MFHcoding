## 0. 本次新增：把病因直接显示在 OLED 上

以前所有诊断信息都走 USART2（PA2/PA3），**看它需要一根 USB-TTL 线**。
现在把最关键的信息搬到了 OLED —— 板子上现成的显示通道，**不接电脑也能读病因**。

### 正常模式

OLED 第 8 行（page 7）常显一行：

| 屏幕显示 | 含义 | 去查什么 |
|---|---|---|
| `NET: ---` | 还没开始联网 | 正常，稍等 |
| `NET: AT no reply` | **模块完全不理你** | 接线 / 共地 / EN 脚 / 供电 / 波特率 |
| `NET: WIFI fail` | 连不上热点 | SSID 密码 / 频段 / 信号强度 |
| `NET: TCP fail` | 连不上巴法云 | 网络不通 / DNS / AP 隔离 |
| `NET: MQTT rc=05` | Broker 拒绝 | 私钥 / 主题（rc 是 CONNACK 返回码） |
| `NET: retry 30s` | 退避重试中 | 正常行为，秒数会一直变；**不变才是卡死** |
| `NET: OK pub=12` | **已连上并成功上报 12 次** | 一切正常 |
| `NET: baud=9600` | **模块真实波特率不是 115200** | 见第 5 节 |

### 自检模式（`NET_SELF_TEST = 1`，推荐先用它）

只跑联网、不启动传感器，OLED 会显示这 6 行：

```
NET SELF TEST
NET: AT no reply          ← 一句话病因
step=1                    ← 卡在第几步: 1=AT 3=热点 4=TCP 5=MQTT, 0=全部通过
AT                        ← 模块最后一句应答(原话, 信息量最大)
rst=0 ovf=0               ← 模块重启次数 / 本机串口接收溢出
err=0                     ← 串口错误事件
baud=115200               ← 当前生效波特率
```

**「模块最后一句应答」这一行最关键** —— 它直接告诉你模块到底说了什么：

| 那一行显示 | 模块在说什么 | 结论 |
|---|---|---|
| （空白） | 一个字都没说 | **硬件层**：接线/共地/EN/供电/波特率 |
| `ERROR` | 命令它不认识 | 该 AT 指令不被此固件版本支持 |
| `FAIL` | 指令执行失败 | 看是哪条（`+CWJAP:x FAIL` = 热点问题） |
| `DNS Fail` | 域名解析不了 | 热点 DNS，看 IP 直连是否生效 |
| `CLOSED` | 连接被对端关掉 | 云端/网络侧断开 |
| `busy p...` | 模块正忙 | 串口被抢，查供电稳定性 |
| `OK` | 一切正常 | 若还连不上，看 step 号 |

## 1. 第一嫌疑：独立供电必须与 STM32 **共地** ⚠️

**你刚说"独立供电"—— 这恰恰是最高发的问题。**

串口通信是**电压差**信号。ESP01S 用独立电源时，它的 GND 和 STM32 的 GND
是两套互不相关的参考电位。如果**两根 GND 没有连在一起**：

* 电平没有共同参考 → STM32 收到的是一串毫无意义的噪声
* 现象就是：**模块灯亮着、热点也连上了（如果它自己连的话），但 STM32 发 AT 完全没反应**
* 这跟"接线接错"长得一模一样，所以极容易被误判

**处置：把独立电源的 GND、ESP01S 的 GND、STM32 的 GND 三者用一根线连在一起。**
只要这一根线，问题可能就没了。

> 用一个万用表量一下 ESP01S 的 GND 与 STM32 的 GND 之间是否导通（阻值≈0）即可确认。

---

## 2. 独立供电的电压必须是 **3.3V**（5V 会烧模块）

ESP-01S 是 **3.3V** 器件，**IO 和 VCC 都不能接 5V**。

* 如果你用的是 USB 口的 5V 直接供 VCC → 模块可能已经损坏或处于异常状态
* 开发板上的"5V"排针也是 5V，不能直接接
* 正确的独立供电：**3.3V LDO 输出**，或用带 3.3V 档的 USB-TTL 模块的 3.3V 脚

**处置：确认你那路独立电源的输出电压是 3.3V。** 若一直是 5V，换一个模块试。

---

## 3. 供电能力：峰值 ~300mA，必须并 100µF

ESP8266 在 WiFi 发射瞬间电流可达 **300mA 以上**。如果：

* 独立电源只有 100mA 能力（例如从某处的小 LDO 取电）
* 或走线细、线长
* 或没加去耦电容

→ 发射瞬间电压被拉低 → **模块复位**。

**判据**：如果能看到 `rst=` 在涨（OLED 上那个 `rst=` 数字不断变大），
就是模块在反复重启 —— **供电不足的铁证**，此时调代码毫无意义。

**处置**：
* VCC 与 GND 之间并一个 **100µF 电解电容**（越靠近模块引脚越好）
* 再并一个 0.1µF 瓷片电容
* 电源线尽量短、粗

## 4. ESP-01S 引脚终检表

| 引脚 | 必须接 | 说明 |
|---|---|---|
| **VCC** | 独立 3.3V（+100µF） | 不能接 5V |
| **GND** | 与 STM32 共地 ⚠️ | 见第 1 节 |
| **TX** | → STM32 **PA10**（RX） | **必须交叉** |
| **RX** | ← STM32 **PA9**（TX） | **必须交叉** |
| **EN**（= CH_PD，同脚不同丝印） | **3.3V** | 悬空会导致模块不启动/随机复位。ESP-01S 板载通常已有上拉，但廉价板可能没有 —— **务必实测确认** |
| **IO0** | **悬空** | 接 GND 会进 flash 下载模式，AT 完全无响应 |
| **IO2** | **悬空** | 接 GND 会进 SDIO 启动模式，同样不响应 |

**自查顺序**：EN 是否 3.3V → TX/RX 是否交叉 → GND 是否共地 → IO0/IO2 是否悬空。

---

## 5. 波特率：AT 完全无应答的隐藏原因（本次新增自适应）

ESP-01S 出厂 AT 固件默认 **115200**。但模块若被刷过固件、或执行过
`AT+UART_DEF` / `AT+UART_CUR` 改过串口参数，真实波特率就可能是 9600 等值。

**这种情况从外表完全看不出来**，现象和"接线坏了"一模一样，很容易让人一直在
接线和供电上打转。

**本次改动**：驱动现在会自动处理。在 115200 下完全无应答时，自动依次尝试
`9600 / 74880 / 57600 / 38400 / 19200 / 230400 / 460800`，扫到就把**真实值**
打出来并锁定：

```
[AT] no reply, scanning other baud rates...
[AT] module baud rate = 9600
```

* 看到 `module baud rate = 9600` → 把 `user_config.h` 的 `ESP01S_BAUD_RATE` 改成 `9600`，以后上电就不必再扫（也省掉每次开机的几秒扫描）
* 看到 `[AT] no reply at ANY baud` → 所有波特率都没应答，**可以彻底排除波特率**，放心去查接线/共地/EN/供电

> 注意：扫描每次只在**第一次失败**时进行，之后不会重复（否则每次重连都要白等好几秒）。
> 想重新扫描，重新上电即可。

## 7. 现在的判读流程

```
烧 NET_SELF_TEST = 1 的固件
        │
        ├─ OLED: NET: AT no reply        → 回第 1~5 节逐一核对(共地最优先)
        │         baud=9600              → 把 ESP01S_BAUD_RATE 改成 9600 即可
        │
        ├─ OLED: NET: WIFI fail          → 热点问题(密码/频段/信号)
        │
        ├─ OLED: NET: TCP fail           → 到不了巴法云(DNS/AP 隔离/网络)
        │
        ├─ OLED: NET: MQTT rc=xx         → 私钥/主题(但本机已实测这两项正常!)
        │
        └─ OLED: step=0, rst=0           → 链路完全正常, 问题在别处
                  ↑ 若 rst 在涨 → 供电不足, 回第 3 节
```

排完问题把 `NET_SELF_TEST` 改回 **0**，恢复正常功能。
