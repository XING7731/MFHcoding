# 28 · "怎么扔都不报警"的四重根因与修复

> 触发问题：**"无论怎么放都会有一个大约 3.9 的加速度，让它下落后蜂鸣器报警 3 秒"**
>
> 这段话里其实是两件事：
> ① **读数不对** —— 静止时 |a| 显示 3.9 而不是 1.0（这是"无论怎么放"那半句）；
> ② **动作不对** —— 掉下去要响 3 秒。
>
> 而"怎么扔都不报警"是 ①② 叠加出来的结果：**读数错了 4 倍，判据就永远
> 不可能成立**。这篇文档把两个问题分开说清，并给出可自证的实验。

---

## 1. 一句话结论

| # | 根因 | 为什么它会让"掉下去也不报警" | 修复 |
|---|---|---|---|
| ① | 换算系数取错，读数被整体放大 4 倍 | 静止读到 3.9g ⇒ 4.0g 的读数既满足不了"< 1.5g 才算稳"，也把真撞击推离阈值 | 运行期**在线标定**（见 §3） |
| ② | 判据挂在 **10Hz** 的任务上 | 撞击只持续 5~20ms，落在两次采样之间的概率 >80%，**信号根本没被看到** | 独立 **200Hz** 撞击监视任务 |
| ③ | DLPF 带宽 **44Hz** 太窄 | 5ms 宽的撞击尖峰被低通滤掉 -14dB，峰值从 1.93g 掉到 1.28g，**够不着阈值** | DLPF 放宽到 **188Hz** |
| ④ | 判据要求"100ms 内**两次**超阈" | 落到软垫/地毯上只有**一次**尖峰，凑不齐"两次" ⇒ 不报警 | 新增**自由落体路径** |

**四条缺一不可**：单独修任何一条，仿真里都还是漏报。这一点在 §4 有量化对照。

---

## 2. 根因①②③：先确认"信号被采到了没有"，再怀疑阈值

上一版的排查方向是**错的**：读数显示 3.9，于是去调阈值（5.0/4.5）。但阈值
只是在"错误的读数体系"里挪动门槛，物理上不可能修好 —— 详见 docs/25、docs/26。

正确的顺序是：

```
先问 "撞击那一刻的波形，到底有没有进到 MCU 里？"
     │
     ├── 没有 → 查采样率、查 DLPF 带宽、查 ODR   ← 本版的②③
     └── 有   → 才轮到查阈值、查判据逻辑          ← 本版的④
```

为了把这件事变成**可观测**的，本版加了两样东西：

- **`FallDetect_GetPeak()`** —— 显示最近 3 秒内的 |a| 峰值。
  扔一次之后看屏幕：
  - 峰值 `2.0` ⇒ 撞击**采到了**（±2g 量程内被削顶），该去查判据；
  - 峰值一直 `1.0` ⇒ 撞击**根本没采到**，该去查采样率与带宽。
- **OLED 第 6 行显示判据瞬时态**（`FALL:FF / IMP / CFM`），不必再靠"扔一次试试"猜状态机停在哪一步。

## 3. 根因①：3.9 是怎么来的，在线标定怎么修

### 3.1 为什么是 4 倍

驱动里按 `MPU6050_ACCEL_FS_G = 8`（±8g，4096 LSB/g）换算，但这颗克隆片的
加速度计**实际锁死在 ±2g**（16384 LSB/g），而且它的 `ACCEL_CONFIG` **连读回
都能伪造成 8g** —— 写什么读什么，骗得过寄存器回读，骗不过物理：

```
静止时 |a| ≡ 1g  （无论板子朝哪个方向 —— 见 docs/27）
⇒ 原始码值模值 ≈ 16384 = 1g 的真实 LSB 数
⇒ 用 4096 去除 → 读数 = 16384/4096 = 4.00g      ← 用户看到的 3.9
```

### 3.2 为什么上一版的自标定"没生效"

上一版的标定是**上电时做一次，且要求静止**。现场是**拿在手里上电**的，
标定条件不满足 ⇒ 标定失败 ⇒ 读数仍被放大 4 倍。**用户每次看到 3.9，就是因为
每次都是拿着它上电。**

### 3.3 本版：运行期在线标定（放稳 1.5 秒自动修正）

`MPU6050_OnlineCalFeed()` 挂在 **200Hz 撞击监视任务**里，逐样本累积原始码值
模值的 `sum / min / max / n`，每 **1.5 秒**评估一次窗口：

| 判据 | 门限 | 含义 |
|---|---|---|
| 极差 `(max-min)/mean` | ≤ 3.0% | 窗口内确实**安静**（没有在动） |
| 均值落在合理区间 | — | 不是全 0（脱线/掉电） |

满足则把均值当作 **1g 的真实 LSB 数**，替换换算系数；不满足则丢弃本窗口、
下一窗口重来。

**关键设计**：偏差大于 10% 时**直接替换**，小于 10% 时按 1/4 平滑。
这样"第一次放稳"就能一次跳到位（1.5 秒内从 3.9 变回 1.0），
之后只做微调，不会来回抖。

> **现场只需要做一个动作：把头盔放在桌上别动 1.5 秒。**
> 屏幕第 2 行的 |a| 会自己从 3.9 回到 1.0，不需要重启。

### 3.4 界面上的自检提示

第 6 行在标定未信任时显示 `! ACAL FAIL`，判断依据是
`MPU6050_IsScaleTrusted()`（= 上电标定成功 **或** 在线标定成功）。
看到 `! ACAL FAIL` 就说明：**现在这个读数还不准，先放稳 1.5 秒**。

## 4. 数值验证：`tools/fall_detect_sim.py`

真机扔一次只能得到一个"报/不报"的结果，说不清**是运气还是设计**。
所以本版把物理、器件、固件三样都在 PC 上复刻出来，用**扫相位**的方式
把"运气"变成"命中率"。

复刻的三层：

```
物理 : 自由落体 |a|≈0 → 撞击半正弦脉冲(峰值 40g, 宽 3~4ms) → 躺稳 1.0g
器件 : ±2g 削顶 → DLPF 二阶低通 → ODR → 主机采样率(取点)
固件 : fall_detect.c 的状态机 + mpu6050.c 的在线标定
```

**方法要点**：撞击时刻不可能正好落在采样栅格上，所以对撞击时刻做
**0~4.875ms 的相位扫描（40 个相位）**，统计命中率。命中率 100% 才叫设计成立；
命中率 50% 说明"报不报看运气"。

### 4.1 结果（14 项全部通过）

| 组 | 断言 | 结果 |
|---|---|---|
| 1 | 路径A + 旧 10Hz 采样 → **漏报** | PASS（峰值仅 1.00g） |
| 1 | 路径A + 新 200Hz 采样 → 报警 | PASS（峰值 1.93g） |
| 1 | 补上路径B 后 **10Hz 也能报** | PASS |
| 2 | 路径A + DLPF 44Hz → **漏报** | PASS（峰值仅 1.28g） |
| 2 | 路径A + DLPF 188Hz → 报警 | PASS（峰值 1.93g） |
| 2 | 补上路径B 后 DLPF 44Hz 也能报 | PASS |
| 3 | 原判据命中率 <100%（依赖相位运气） | PASS（0/40） |
| 3 | 路径B 落地门限沿用 1.8g → **仍漏报** | PASS（20/40） |
| 3 | 路径B 落地门限 0.9g → **100%** | PASS（40/40） |
| 4 | 拿起放下 5cm → 不报警 | PASS |
| 4 | 走路磕碰（单次撞击无失重）→ 不报警 | PASS |
| 4 | 拿起搬运放下（抬手 1.3g，不失重）→ 不报警 | PASS |
| 5 | 换算错 ×4 且未修正 → **漏报** | PASS |
| 5 | 在线标定修正后 → 报警 | PASS |

> 第 1、2 组特意**把路径B 关掉**（`Detector(use_freefall=False)`）来做对照。
> 如果直接拿完整检测器跑，路径B 会把 10Hz 也救回来，**就看不到"采样率是病根"
> 这件事了** —— 而这条认识恰恰是最重要的。所以隔离测试是必须的。

## 5. 本版修掉的第二个真 bug：路径B 自己的"落地"判据

这是这一轮最有价值的发现，**因为它伪装成"已经修好了"**。

### 5.1 现象

路径B（自由落体）加进去之后，仿真里仍然 **40 个相位只命中 20 次（50%）**。

### 5.2 原因

路径B 的第二步写的是"等撞击"，而门限**沿用了路径A 的 `HIGH_G = 1.8g`**：

```
撞击脉冲高于 1.8g 的时间只有 1~3ms  ← 主机 5ms 采一次
⇒ 采不采得到全看相位 ⇒ 命中率 50%
```

**它继承了它本该绕开的那个采样竞态。** 路径B 的整个立意就是"绕开撞击幅度
这件事"，结果在最后一步又把它请了回来。

### 5.3 正确语义

一旦"持续失重 150ms"已经确认，剩下要问的**只有一件事**：

> **失重结束没有？**

而失重平台（|a| ≈ 0g）与静止（|a| = 1.0g）之间**整整差着一个 g**，
过渡又宽又慢 ⇒ 跨越点必然落在极宽的时间窗上，**与采样相位无关**。

所以这个门限**故意取得远低于撞击量级** —— 它不是"撞击判据"，
它是**"落地判据"**，撞击量级的事交给后面的确认流程。

### 5.4 取值：仿真扫出来的敏感度

| 落地门限 | 命中率 | |
|---|---|---|
| 0.6g | 40/40 | 也可，但离失重门限 0.5g 太近 |
| 0.7 / 0.8 / **0.9** / 1.0g | 40/40 | **采用 0.9g** |
| 1.2g | 36/40 | 开始掉 |
| 1.4g | 30/40 | |
| 1.6g | 25/40 | |
| 1.8g | 20/40 | ← 上一版的写法 |

**0.6~1.0g 都拿满分**。取 `0.9g` 而不是 `0.6g`，是给失重平台的纹波/噪声
留一倍余量：0.6g 只比失重门限 0.5g 高 0.1g，真机上的噪声余量太薄。

## 6. 顺带补上的第三个洞：稳定带必须有下沿

条件3 原来只写 `|a| < 1.5g`，这在物理上是个**漏勺**：

```
自由落体 |a| ≈ 0.02g   →  也小于 1.5g  →  会被当成"躺稳了"
```

于是"掉到一半擦到桌沿、接着继续往下掉"这种情况会被判成"稳定"，
再数满 1.5 秒就**误报警**。修复是给稳定带加上下沿：

| 状态 | \|a\| | 落在稳定带 [0.8, 1.5) 内？ |
|---|---|---|
| 自由落体 | 0.02g | **否** ← 下沿挡的就是这个 |
| 静止躺地 | 1.00g | 是（无论帽子朝哪个方向） |
| 剧烈晃动 / 连续碰撞 | > 1.5g | 否（上沿挡的） |

**下沿的物理含义**："被支撑着"（受重力 ⇒ |a| ≈ 1g）而不仅仅是"不动"。
取 `0.8g` 而不是 `0.95g`：落地后壳体会轻微回弹/滚动，留余量；同时离 1.0g
足够近，标定略有漂移也不至于判不出来。

## 7. 报警行为：3 秒连续长鸣

需求是"报警 3 秒"。`AlarmTask` 按事件紧急程度分两种声音：

| 类型 | 声音 | 用途 |
|---|---|---|
| **紧急**（摔倒） | **连续长鸣 3000ms** | 出事，必须立刻被听见 |
| 其它（气体/心率/提示） | 200ms 断续 | 提示，不吓人 |

**"报警"和"提示"必须能被耳朵区分开** —— 报警时不能让人误以为又是普通提示音。

超时后由事件队列自动关闭（`FALL_ALARM_MS = 3000`），不依赖状态机复位。

## 8. 上电后怎么验证（三步）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 上电，**放在桌上别动 1.5 秒** | 第 2 行 \|a\| 从 3.9 → **1.0**；第 6 行的 `! ACAL FAIL` 消失 |
| 2 | 把头盔从桌面（约 70cm）**放手让它掉到地上** | **连续长鸣 3 秒** |
| 3 | 若第 2 步没响 | 看第 7 行 `P<峰值>`：**2.0 ⇒ 撞击采到了**（查判据）；**1.0 ⇒ 没采到**（查采样率/带宽），并把第 6 行 `FALL:xx` 的状态变化抄下来 |

> 第 3 步是这篇文档最有用的部分：**它把"不报警"拆成了两个互斥的可能**，
> 不必再猜。

## 10. 已知取舍：高处抛接会报警

把头盔**向上抛约 30cm 再用手接住**：失重约 247ms（已过 150ms 门限），
接住后手不动读数也接近 1.0g ⇒ **会报警**。

两点说明：

1. **这不是本版引入的** —— 上一版（落地门限 1.8g）同样会报警，因为接住那一下
   的冲击通常也超过 1.8g。
2. 若要排除它，**正确做法是把 `FALL_FREEFALL_MIN_MS` 提到 250ms**（≈31cm 起落），
   **而不是把落地门限调高** —— 调高落地门限会立刻把命中率拉回 §5.4 那张表。

## 11. 方法论：这次的教训可以复用到任何"传感器检测不触发"的问题上

1. **先确认信号有没有被采到，再怀疑阈值。**
   `10Hz` 采 `5ms` 的脉冲，是"根本没看见"，调阈值调一辈子也没用。
2. **采样率、带宽、阈值必须一起看。**
   三者是乘法关系：任一环节把信号吃掉，后面全废。
3. **把"运气"变成"命中率"。**
   真机扔一次只能看到一次结果。要做相位扫描，命中率 100% 才算设计成立。
4. **修完要回头量一次，别信"看起来对了"。**
   路径B 在 `1.8g` 门限下"看起来已经修好了"，实际只有 50% ——
   这个 bug 是被**仿真扫相位**抓出来的，不是被读代码看出来的。
5. **小心"漏勺判据"**：`|a| < 1.5g` 这种单边条件，
   很容易把"读数≈0"（失重、脱线、量程外）这种**异常状态**误判成"正常"。
   该给下沿的时候必须给。
