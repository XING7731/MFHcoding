# 33 · 小程序趋势页：从 CSS 柱子改成 canvas 折线图（温湿度双轴）

> 需求："给我的小程序里加上图形，比如温湿度的图形"
>
> 实测日期：2026-09-18
> 交付位置：`C:\Users\27362\Desktop\WeChat smart helmet`
>
> 结论一句话：**趋势页原来画的是一排 CSS 柱子 —— 它只能看"谁大谁小"，
> 看不出走势，也看不出哪一段是断的。这一版换成自己写的 canvas 折线图
> （不引入任何 npm 图表库），并把"折线遇缺测必须断开"做成受断言保护的行为。**

---

## 一、原来那版到底缺什么

原实现（`pages/trend/trend.js` 的 `render()`）是把每个数据点的高度算成百分比，
交给 40 个 `<view class="bar">` 撑高度：

| 问题 | 具体表现 |
|---|---|
| 看不出**走势** | 一排柱子看不出"温度在缓慢往上爬"还是"一直在抖" |
| 看不出**断点** | 心率没测到（null）时柱高记 0，视觉上和其他矮柱子一样，看着像"心率掉到 0" |
| 看不出**门限** | 40℃ 高温线、50 气体报警线在图上不存在，得自己拿眼睛比 |
| 一屏只有 **40 根** | 缓存 60 个点却只能画后 40 个，前 20 个静默丢掉 |
| 温湿度**不能同屏** | 只能一次看一个指标，判断"是不是又闷又热"要来回切 |

对一个"现场巡检 + 报警"的界面来说，**"心率掉到 0"和"心率没测到"是两件
完全不同的事**，柱子图把它们画成了同一根矮柱 —— 这是必须改掉的第一条。

---

## 二、方案选型：为什么不装图表库

| 方案 | 结论 | 理由 |
|---|---|---|
| `ec-canvas`（ECharts 小程序版） | ✗ | 要"构建 npm"；包体大（ECharts 压缩后数百 KB），而本工程一直避免引入构建步骤 |
| F2 / wx-charts 等 | ✗ | 同上；且多数依赖旧版 `wx.createCanvasContext` |
| WXML/CSS 硬拼折线 | ✗ | 每一段斜线要靠 `transform: rotate(θ)` 单算角度，rpx 下误差会被放大；断点、刻度全都得自己拼，代码量不比 canvas 少 |
| **自己写 canvas 2d 折线** | ✓ 采用 | 与 `utils/mqttws.js`（手写 MQTT 而不装 mqtt.js）同一个取向：**不引入构建步骤，出问题能直接读代码定位**；代价是绘图逻辑要自己维护，所以配了 93 项断言 |

`<canvas type="2d">` 需要基础库 2.9.0+，本工程 `libVersion: "trial"`，满足。

## 三、结构：把"画什么"和"落到画布"拆开

```
utils/chart.js          ← 新增，不依赖任何 wx API
  extractSeries()       取一列数，缺测占位为 null（保持长度与索引一致）
  niceScale()           由数据范围算出"包得住数据"的刻度
  buildPlan(cfg)        把数据折成一串【绘图原语】：
                        { t:'line', pts:[[x,y],…], color, width }
                        { t:'area' | 'dot' | 'text' }
  drawPlan(ctx, plan)   十几行 switch，逐条落到 ctx 上
pages/trend/trend.js    ← 组装 cfg、取 canvas 节点、调上面两个函数
```

**为什么要这么拆**：这台机器上没有微信开发者工具的命令行，canvas 画出来的
像素没法看。拆开之后，真正会算错的东西 —— 折线断点、刻度范围、双轴换算、
孤点有没有丢 —— 全部变成"对着一串数字做断言"，可以在 Node 里逐项验证
（`tools/wxmp_chart_test.js` 的 A 段与 B 段）。

还有一个更隐蔽的理由：`buildPlan` 如果发了一种 `drawPlan` 不认识的类型
（比如写成 `'polyline'`），图会**静默空白**、不报任何错。
所以测试里有一条 B0：**两个模块对"原语类型集合"的认知必须一致**。

## 四、六个关键设计决定（含被否掉的做法）

### 4.1 缺测必须断开，不许连过去 ★

心率/血氧在未佩戴时是 `null`。折线图默认行为是"跳过缺测、把前后两点连起来"，
那等于在图上报一个**根本没测到的值**。在一个报警系统里这是不能接受的谎。

做法：`extractSeries` 让缺测**占位为 null 且保持索引对齐**（不能"跳过"，
否则缺测之后的点整体左移，时间轴就整体错位了）；`buildPlan` 遇到 null 就
结束当前折线段、另起一段。

测试 A5 直接卡这一条：`values = [26,27,null,null,25,24]` 必须切成
**2 段、每段恰好 2 个点** —— 只要有人在 null 处"补"一个点，这条立刻红。

### 4.2 孤点画成圆点，不能丢

前后都被缺测夹住的一个有效值（`[null,27,null]`）连不成线。若只画 `len>=2`
的段，这个**真实测量值就凭空消失了**。所以长度 1 的段单独画一个圆点
（测试 A6）。

### 4.3 温湿度用双 Y 轴

温度 26~30℃、湿度 45~65%RH，量级差近十倍。共用一套刻度会怎样？
测试 C3 把它量化了：**每根线各自纵向只会用到约 2%~12% 的高度**（两根都压成平线）；
分轴之后各用掉 55% 与 69%。断言写成"两根线各自的纵向跨距都必须 > 40%"，
共用刻度的写法过不了。

右侧刻度数字用**湿度那根线的颜色**，否则人不知道该读哪一边（测试 A7）。

配套否掉的做法：**双序列不画面积填充** —— 两块半透明叠在一起会糊出第三种颜色，
看着像有第三条曲线（测试 A7 卡 `area` 条数为 0）。

### 4.4 阈值线只在坐标范围内画，且不为它拉轴

单指标视图会画固件门限（温度 40/10℃、气体 50、心率 120/50、血氧 90、
合加速度 1.8g）。两条约束：

> 🔻 2026-09-22：光照视图（及其 400 阈值线）已随光照功能整体删除，见 `docs/39`。
> 撞击门限当时还是 2.5g，现已更正为 **1.8g**。

- **不在显示范围内就不画**。为了画一条 40℃ 的线把纵轴从 26~30 拉到 0~40，
  曲线会被压成一条直线 —— 那是得不偿失的。
- **也不许反过来让轴去迁就门限**。

测试 A8 / C4 同时卡这两条：温度 26~27 时 0 条门限线且 `scale.max < 40`；
心率 80~91 时 0 条且 `scale.max < 120`；温度顶到 42 时恰好画出 1 条（10℃ 那条
仍在范围外）。双序列视图一律不画（说不清属于哪根轴）。

> 取舍说明：这意味着**"门限离数据很远时图上看不到门限"**。
> 这是有意的：图的职责是看清波动，门限是否越界由首页的门限提示负责。

### 4.5 数据全相等时也要把轴撑开 ★

湿度稳定在 55.0 时 `max - min = 0`，`y = (v-min)/(max-min)` 直接除零 →
所有点变 NaN → **整张图空白，且不报错**。原柱子图对这种情况打了补丁
（`pct = 60`），折线图必须在刻度层解决：撑开 ±10%，让这条平线落在图中间。

测试 A3 + A2 的 12 组范围里包含 `[55,55]`、`[0,0]`、`[3.9,3.9]`、`[100,100]`
四种全相等情形。

### 4.6 两个 canvas 专属的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **节点在 `wx:if` 里** | 图表外层是 `wx:if="{{!empty}}"`，"数据从无到有"那一次 `setData` 之后立刻查节点会**查不到**，图一片空白 | `setData` 后经 `wx.nextTick` 再取节点（测试 C7 覆盖） |
| **高清屏发虚** | 不放大背板，线是糊的 | `canvas.width = 布局宽 × devicePixelRatio`，再 `ctx.scale(dpr, dpr)`（测试 C7 断言 300×150 → 600×300 且 `scale(2,…)` 被调用） |

另外纵轴留了 6% 余量：不留的话，最小值恰好落在整步长上时（比如温度正好 26.0），
最低那个点会贴着底边轴线，看着像被切掉。

## 五、顺带改掉的一处：缓存 60 → 240 点

折线图要有意义得有足够的横轴长度。板子 10s 一条，原来 60 点 ≈ 10 分钟，
只看得到一小段。改为 **240 点 ≈ 40 分钟**（`app.js` 的 `keepPoints`）。
代价：每点约 110 字节 JSON，240 点 ≈ 26KB，远低于单个 storage key 1MB 的上限。

### 必须说清的边界

**我没有在微信开发者工具或真机上跑过。** 上面所有断言证明的是
"算出来的绘图计划与数据一致、原语都落到 ctx 上了"，
**没有证明"像素好不好看"**：字体大小、折线粗细、颜色搭配、
`canvas` 在不同机型上的实际渲染，都只能进开发者工具看一次。

它比截图更能说明问题。

## 八、已知限制（写进报告时别漏）

1. **仍看不到 40 分钟以前的数据** —— 平台接口不给历史（docs/23 已实测），
   趋势完全靠本机缓存，卸载小程序或清空即丢。
2. **x 轴只标 3 个时刻**（首/中/末）。点数多时挤不下；不支持缩放与手势拖动。
3. **不画门限的情况**：门限离数据很远时看不到（见 4.4，是有意取舍）。
4. **稀疏数据下的孤点**：心率只有零散几拍有效时会是一串点而不是线，这是数据的
   真实样子，不是画错。
5. **坐标系未做时间等距处理**：x 按**点序号**均分。板子严格 10s 一条时与等距
   等价；若某段时间断连（seq 跳号），那一跳在图上不会显示为一段空白。
   要修需要按 `unix` 换算 x —— 目前判为不需要，但要如实说明。
