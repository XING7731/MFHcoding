# 30 · 贴手后 3 秒稳定期 + OLED 去掉时间行

> 触发问题（用户原话，三件事）：
> ① **"心率和血氧测量还是会误测"** —— 上一版（docs/29）修完四个算法缺陷后，仍然不准；
> ② **"改成手放上去后 3 秒再开始监测，防止读数不准"**；
> ③ **"测量时在 OLED 上显示，再把 OLED 上的时间去掉，只留下关键信息"**。
>
> ①看起来像"再加个延时"，**实际不是**。数值仿真（`tools/ppg_contact_sim.py`）
> 挖出了**第五个独立缺陷**，而且它是四者里最狠的一个 ——
> **贴手后 34 秒内一个有效心率都出不来**。这一篇把它讲清楚。

---

## 1. 一句话结论

| # | 根因 | 量化证据 | 修复 |
|---|---|---|---|
| **⑤** | **直流阶跃进了交流通道**（新一轮真凶） | 手指盖住时 IR ≈ 50000、拿开时 ≈ 300，**差 167 倍**。上电时没手指，高通直流估计早衰减到几百；手指一贴上，这一跳被整个当成"交流"输出 ⇒ 假峰 **36422**（真实脉搏波 600 的 **61 倍**）⇒ 峰值参考被顶到 36422、峰阈值抬到 14569 ⇒ **贴手后 34160 ms 才出第一个数** | `PPG_DC_STEP_FRAC` **直流阶跃吸附**：跳变超过 25% 就把直流估计直接吸附过去，跳变不进入交流通道 |
| ⑥ | 「只加接触锚定」堵不住它 | 接触判定带去抖（300ms）才生效，而阶跃发生在**第 1 毫秒** ⇒ 仿真里 anchor 变体的假峰**依然是 36422**，和没修一样 | 吸附**不等去抖确认、当场生效**；锚定只负责清残余拍库，两件事分开 |
| ⑦ | 用户要求的 3 秒稳定期 | 门控期算法内部本来就会算出数（贴手瞬间滤波器还在收敛、指尖受压血容量在重分布），旧行为直接显示出去 | 三态机 + `HR_GetResult()` 里**统一门控**（屏上和云端同一个判断） |
| ⑧ | OLED 时间行没人用 | 设备 RTC 无备份电池（断电即失），时间以云端为准；上行报文里带 `HH:MM:SS` 才是权威值 | 去掉时间行，**行0 改放 PPG 测量状态** |

**⑤ 是主要矛盾。** ⑦ 是用户明确要求的、也确实该有，但**它不改变算法结果**，
改变的是"什么时候让用户看到"—— 这一点在 §4 有诚实的代价量化。

## 2. 为什么仿真能挖到这一条：上一版测漏了什么

`tools/ppg_hr_sim.py`（docs/29）覆盖的是**手指一直在传感器上**时的算法缺陷。
它默认了一个前提：**波形从头到尾都有脉搏**。

但真实使用流程是：

```
上电 ──(没有手指, 只有环境光)──► 过一会儿才把手指放上去
        ↑ 这段才是误测的发生地, 而上一版从没测过
```

这个洞一补上，问题立刻现形。

---

## 3. 机制：一次阶跃如何变成 34 秒的黑窗

### 3.1 阶跃本身

高通滤波器的核心是 `hp = x - dc`，其中 `dc` 是缓慢跟随的直流估计。
没手指时输入 ≈ 300，`dc` 就衰减到几百。手指一盖上：

```
第 1 个样本:  x = 50000,  dc = 300
              dc += 0.0609 × (50000 − 300) = 3326
              hp  = 50000 − 3326 = 46674      ← 整个直流被当成交流
              lp  += 0.395 × 46674 = 18440    ← 带通输出 ≈ 1.8 万
```

而真实脉搏波只有 **600**。差 **61 倍**（仿真实测峰值 36422，含 lp 的累加过程）。

### 3.2 为什么后果这么严重

这个尖峰被寻峰逻辑当成一次**真实搏动**，于是：

```
amp_ref = 36422        （峰值参考，自适应阈值的基准）
阈值 = 0.40 × amp_ref = 14569
```

之后真实脉搏波（600）**永远过不了 14569 的阈值**。唯一的解救通道是
"连续 6 秒没峰就把 `amp_ref` 减半"：

```
36422 → 18211(6s) → 9105(12s) → 4552(18s) → 2276(24s) → 1138(30s) → 569(36s)
                                                              ↑ 阈值 228 < 600, 终于能看见
```

**仿真实测：贴手后 34160 ms 才出版第一个数。**

这就是"读数随机"最直白的现场来源 ——
用户贴上手指，屏上长时间没反应，然后**突然蹦出一个数**。
前后都没有解释，任何人在现场都会说它是"随机的"。

> 注意这里的数值是**按真实器件量级取的**（手指盖住几万、拿开几百），
> 不是为了让结论好看而放大的。

## 4. 三层修法的作用分解（`tools/ppg_contact_sim.py`，17/17 断言 PASS）

四个变体跑**同一段波形、同一随机种子**，把每个修法的贡献分开：

| 变体 | 说明 | 贴手后 600ms 内的峰 | amp_ref | 首次出数 |
|---|---|---|---|---|
| `old` | 09-16 版：无接触判定 | **36422** | 36422 | **34160 ms** |
| `anchor` | 只加"接触确认后清算法 + 锚定直流" | **36422** | 36422 | 3320 ms |
| `snap` | 再加**直流阶跃吸附** | 无（598） | 598 | 3320 ms |
| `new` | 再加 **3 秒稳定期门控** | 无（598） | 598 | 3320 ms |

读法：

1. **`old → anchor`**：出数时间从 34 秒回到 3.3 秒 —— 但注意 **假峰依然是 36422**。
   也就是**锚定并没有挡住阶跃**，它挡住的是"阶跃把 `amp_ref` 顶死之后没人清理"。
   这是个巧合性的救命：靠 300ms 后 `clear_algo()` 把污染擦掉。
   一旦手指只是轻微挪动、没触发状态迁移，就没有这次清理，污染会一直留着。
2. **`anchor → snap`**：**假峰从 36422 变成 598（= 真实脉搏波量级）**。
   这才是从根上把问题消掉 —— 跳变根本不进入交流通道，不产生假峰，
   也就不依赖后续任何清理动作。
3. **`snap → new`**：算法结果**没有任何变化**，变的只是"什么时候对外发布"。

### 4.1 稳定期门控的诚实代价

门控期固定 `300ms(去抖) + 3000ms = 3300ms`。而算法自己需要
"1 个锚点峰 + 3 拍 IBI"，**心率越慢这个时间越长**，所以门控的代价只出现在心率偏快时：

| 真值 | `snap` 出数 | `new` 出数 | 门控代价 |
|---|---|---|---|
| 50 bpm | 5160 ms | 5160 ms | **+0 ms** |
| 72 bpm | 3300 ms | 3300 ms | **+0 ms** |
| 90 bpm | 3140 ms | 3280 ms | +140 ms |
| 110 bpm | 2940 ms | 3280 ms | +340 ms |

**最坏 340ms。** 心率偏慢时 3 秒甚至还不够算法自己攒够拍数，门控等于零代价。

> **必须说实话**：在仿真的这几个场景里，门控**一次都没有真正挡住过非零输出** ——
> 因为算法本来就要到差不多那个时刻才攒够拍数。
> 所以门控的定位是：**把"贴手后必然存在、但还不可信的那几秒"从"一个会变的数"
> 变成"一句明确的倒计时"**，而不是修掉某个错误读数。
> 真正把误测修掉的是**直流阶跃吸附**。

## 5. OLED 布局：只动第 1 行

```
第1行  PPG 测量状态      ← 原为时间行，现改为测量状态（下面详述）
第2行  HR:72 SpO2:94%~   心率 / 血氧
第3行  T:26.5C H:58%     温度 / 湿度
第4行  GAS:120           气体（2026-09-22 起 LIGHT 段已随光照功能删除，见 `docs/39`）
第5行  A:0.0 0.1 1.0|1.0 三轴加速度 + |a|
第6行  状态（报警 / 传感器异常 / 摔倒瞬时态 / PPG 中间量）
第7行  UP:00:12:34 P1.0  运行时长 + 最近 3 秒 |a| 峰值
第8行  NET: OK p=26 e=26 联网诊断
```

**只有第 1 行的内容变了，其余行号一个都没动。**
这不是凑巧 —— 是刻意这么排的：`docs/14`、`docs/15`、`docs/16`、`docs/22`、
`docs/28`、`docs/29` 里所有"第 N 行"的引用**全部仍然有效**，
不需要跟改十几篇文档。整体上移一行会更"整齐"，但会让那些排查指南指向错行 ——
**文档指错行比少一行更危险**。

### 5.1 第 1 行显示什么

| 显示 | 含义 |
|---|---|
| `PPG: sensor NG` | 芯片不在 I2C 总线上（接错/没供电/地址不对）→ 转 `docs/14` |
| `PPG: warming up` | 在线上，但预热样本还没攒够（100 个 ≈ 2 秒） |
| `PPG: put finger on` | 未检测到手指 → **此时第 2 行是 `HR:--` 是正常的** |
| `PPG: settling in 2s` | 已贴上，稳定期还剩 2 秒 → **此时没数也是正常的** |
| `PPG ready   R:0.72` | 稳定期已过，进入正式测量；`R` 是血氧用的比值 |

**这一行的意义是把两件事分开**：
第 2 行说"**有没有数**"，第 1 行说"**为什么没有数**"。
在此之前，`HR:--` 既可能是"没贴"，也可能是"没测出来"，屏上长得一模一样。

`R` 值常显是附带的收益：血氧标定（`docs/03`）要的就是它，
以前只能在调试串口看，现在拿一台指夹血氧仪对着屏抄点就行。

### 5.2 为什么时间可以去掉

- 设备 RTC **没有备份电池**，断电即失 —— 屏上那个时间本来就不可靠；
- 时间以**云端为准**，上行报文里带的 `HH:MM:SS` 才是权威值；
- 它占了屏幕最顶上、最显眼的一行，却是全屏**唯一一个没人拿来判读**的信息。

去掉它换上"测量状态"，是把最好的位置给了最需要看的东西。

## 6. 参数与接口

### 6.1 新增配置（`user/Inc/user_config.h`）

| 宏 | 值 | 含义 |
|---|---|---|
| `PPG_DC_STEP_FRAC` | `0.25f` | **直流阶跃吸附阈值**（本轮最关键）。真实 PPG 调制比只有 0.5%~5%，而手指贴上/拿开是几十倍量级，两者差三个数量级，25% 谁都碰不到谁 |
| `PPG_CONTACT_RAW_TH` | `2000.0f` | IR **原始值**下限。用原始值不用滤波值：零延迟，手指一盖上立刻越界 |
| `PPG_CONTACT_ON_MS` | `300` | 连续 300ms 判定有手指才算"贴上"（去抖） |
| `PPG_CONTACT_OFF_MS` | `800` | 连续 800ms 判定无手指才算"拿开" |
| `PPG_SETTLE_MS` | `3000` | 稳定期 |

### 6.2 状态机与接口（`heart_rate.h` / `heart_rate.c`）

```c
typedef enum {
    HR_ST_IDLE      = 0,   /* 没检测到手指 */
    HR_ST_SETTLING  = 1,   /* 已贴上，稳定期内（不发布读数） */
    HR_ST_MEASURING = 2    /* 稳定期结束，正常输出 */
} HR_State_t;

HR_State_t HR_GetState(void);
uint32_t   HR_GetSettleRemainMs(void);   /* 倒计时，供屏上用 */
uint8_t    HR_IsTouched(void);
```

**发布门控做在 `HR_GetResult()` 里，不在显示层。**
这样屏上和上行报文走的是**同一个出口**，不会出现"屏上没数、云端却有数"的对不上账。
`HR_IsSignalOk()` 也一样：非 `MEASURING` 一律返回 0，
所以稳定期里算出来的数**也不会触发"心率异常"报警**。

### 6.3 为什么 `begin_settle()` 里还要锚一次直流

阶跃吸附已经当场生效了，锚定看起来多余。保留它是因为两件事不一样：

| | 负责什么 | 生效时机 |
|---|---|---|
| **阶跃吸附** | 不让跳变**变成假峰** | 第 1 毫秒，不等确认 |
| **接触锚定 + 清算法** | 清掉**上一次次测量**的残余拍库（IBI 历史、窗口、amp_ref） | 确认贴上时 |

少任何一个都会出问题：只有锚定 → 300ms 内假峰照样产生（§4 的 `anchor` 变体）；
只有吸附 → 两次测量的拍数会混在一起。

## 7. 数值验证：`tools/ppg_contact_sim.py`

```bash
python tools/ppg_contact_sim.py      # 输出 ppg_contact_sim_result.txt
```

**17 项断言全部 PASS。** 覆盖：

| 场景 | 验证内容 |
|---|---|
| 一 | 阶跃假峰存在（old/anchor 36422）且被吸附消掉（snap/new 598） |
| 二 | 旧版黑窗 34160 ms；吸附后 3320 ms 出数、偏差 −1 bpm |
| 三 | 稳定期内 0 条发布；稳定期结束后 20ms 就出数；首值偏差 ≤3 bpm |
| 四 | 反复贴/拿：拿开 1 秒内停止发布；重贴后稳定期内 0 条发布；重贴后仍出数（73 vs 72） |
| 五 | 测量中压力突变（直流 50000→58000）：偏差 ≤1 bpm，不产生假数 |
| 六 | 弱信号（幅度 600→150、噪声 8→14）：稳定期内仍 0 条发布，之后能出数 |
| 七 | 门控代价 vs 心率：最坏 340 ms |

**关于场景五的一个反直觉结论**：把直流*抬高*造成的向上阶跃，
在新旧两版里**都没有读出假数**（都稳定在 71 bpm）——
因为 IBI 离群剔除（`PPG_IBI_TOL_PCT`）本来就防住了这一类。
所以阶跃的真正危害不是"读出错数"，而是**把 `amp_ref` 顶死后进入长时间黑窗**（§3）。
这也说明：**"误测"在现象上可能是"没数"，不是"数错"。**

## 8. 烧录后验收（5 步，全在 OLED 上看）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 上电，**不碰传感器** | 第1行 `PPG: put finger on`；第2行 `HR:-- SpO2:--` |
| 2 | 食指轻盖光学窗口，**保持不动** | 第1行立刻变成 `PPG: settling in 3s`，**3 → 2 → 1 倒计时** |
| 3 | 倒计时归零 | 第1行 `PPG ready  R:0.7x`；第2行出现 `HR:7x SpO2:9x%~` |
| 4 | 手指继续不动 | 心率稳定 ±2 bpm，**不再乱跳** |
| 5 | 移开手指 | 约 0.8 秒内第1行回到 `put finger on`，第2行回到 `HR:--`（**不留旧值**） |

**若第 3 步出不来数**，看第 6 行（PPG 中间量）：

| 第6行 | 判断 |
|---|---|
| `d≈0` | 压根没采到光 → LED 没亮 / 没盖住光学窗口 / 模块异常 |
| `d` 正常、`a≈0` | 有光但**没有脉搏波** → 贴合不好 / 压力过大 |
| `d`、`a` 都正常 | 信号已有，等算法锁定 |
| 末尾 `DRP` | FIFO 溢出丢样本 → 查 I2C 读取节奏 |

**若第 2 步一直是 `put finger on`**（贴了但没识别）：
IR 原始值没超过 `PPG_CONTACT_RAW_TH = 2000`。此时第 6 行的 `d` 会是几百 ——
说明光没回来，属于**光学/结构问题**（窗口脏了、模块没对准），不是算法问题。

## 9. 已知取舍（如实记录）

1. **拿开手指后约 0.8 秒内仍显示最后一个数**（`PPG_CONTACT_OFF_MS` 去抖）。
   这是刻意的：去抖太短的话，手指稍微一挪就会重启一次 3 秒稳定期。
2. **血氧可能比心率再晚约 1 秒**。血氧要等 4 秒滑动窗口（200 样本）填满，
   而稳定期只有 3 秒。屏上会先出现 `HR` 再出现 `SpO2` —— 正常，不是故障。
3. **稳定期与"没贴手指"在云端报文里看不出区别**（都是 `hr_valid=0`）。
   报文没有加"测量状态"字段：那要同时改 JSON、精简格式和小程序，
   而 `hr_valid=0` 已经表达了"这个数别用"。**需要区分的话说一声，加上很快。**
4. **稳定期不解决运动伪影**。手在动、帽子松、强环境光造成的失真依旧存在
   （需要加速度计做自适应滤波，见 `docs/03` 的局限说明）。
5. **`PPG_SETTLE_MS = 3000` 是按用户要求定的**，不是仿真扫出来的最优值。
   仿真显示它对心率 ≤72 时是零代价，对 110bpm 有 340ms 代价。
