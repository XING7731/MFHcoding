# 36 · 提高心率测量成功率 —— 出数率扫描与 LED 电流调整

> **起因**：用户问「怎么将测量成功率提高」。
>
> 上一轮（docs/35）做的是「让小程序把话说对」—— 让 `ps=3 + hr=null` 不再被
> 显示成「未佩戴」。那只解决「看不懂」，没解决「测不出来」。这一轮回答后者。
>
> **一句话结论**：能拧的旋钮里，只有一个经得起复核 —— **提高 LED 电流**。
> 已从 `0x24`(7.2mA) 改到 `0x4F`(15.8mA)。另外两条在初扫时看着有效、
> 复核后收益消失，一并写在这里免得下次再推一遍。

## 1. 先更正上一轮的一个错误（它正好会把结论带偏）

docs/35 第 203 行原本写着：

> ❌「而 docs/32 记录过**实测**脉搏波幅度只有 150 LSB，漂移却到 400 —— 信号确实是偏弱的。」

这句话是**错的**。`150` 和 `400` 是 `tools/ppg_measure_sim.py` 里弱信号场景的
**仿真参数**（`WEAK = 150.0`、`DRIFT = 400.0`），不是任何一次实测。

工程里真正的实测样例是 `PPG d:58234 a:312`（docs/15 §二、docs/16 §四都引用了它），
而 docs/16 对它的判定是**「光路完全打通了」** —— `a=312` 落在 docs/15 判读表的
「几百~几千」正常档，是 `PPG_PEAK_MIN_AMP = 30` 的十倍。

**为什么要专门写这一条**：把仿真参数当实测，会直接得出「信号弱 → 调 LED 电流」
这个**方向正确但依据错误**的结论。而这一轮真正的发现是：方向对，但**幅度被
严重低估了** —— 不是「从 150 提到 300」这种微调，而是「翻倍才算够」。详见 §4。

## 2. 方法：怎么把「提高成功率」变成能比较的数字

「成功率」这个词本身不可计算，先把它拆成三个互斥的出口：

| 量 | 定义 | 它是什么 |
|---|---|---|
| **出数率** | 给出结果且 `|偏差| ≤ 5 bpm` 的比例 | 要提高的就是它 |
| **错值率** | 给出结果但 `|偏差| > 5 bpm` 的比例 | **底线：必须一直是 0** |
| **无结果** | 明确报「没测到」的比例 | 宁可这样，不要给错数 |

三个必须一起看。只看出数率会被带偏 —— 放宽判据总能把出数率刷上去，
代价全在错值率那一列（§4 12-E 就是这个现象的最干净例子）。

**复用固件仿真而不复制算法**：`ppg_measure_sim.py` 是「可执行规格」，算法与
`heart_rate.c` 一一对应，且它的关键常量（`LP_A` / `HP_A` / `TH_FRAC` / `MIN_AMP` /
`MEASURE_S` / `WIN_IBI_MIN` / `CONSIST_PCT` / `NOTCH_RATIO`）在算法函数体内都是
**模块级直接引用** —— 所以 `setattr()` 就能扫，不必抄一份算法。
抄一份的坏处是「抄错不报错，只让结论变成自证」。

**口径**：每档 3 个真值心率（60/72/90）× 8 个噪声 realization = 24 次；
模式取 `'fix'`（= 固件当前行为）。

**amp 与实测 a 的对应**：仿真的 `amp` 是输入幅度，固件的 `a` 是带通后的交流峰值，
两者只有数量级关系。按 `PK = 1.023`（波形峰值/幅度，数值算出）折算，
实测样例 `a = 312` 对应 `amp ≈ 305`。

## 3. 第一轮扫描：看起来参数完全没问题（以及为什么这个结论不能信）

`ppg_measure_sim.py` 的漂移模型是 `400 · sin(2π · 0.25 · t)` —— **单一频率、
严格周期**。在这个模型下扫出来的结果：

| 档位 | 出数率 | 错值率 |
|---|---|---|
| 幅度 305（= 实测 a:312 档） | **100%** | 0% |
| 幅度 150（弱信号） | 100% | 0% |
| 幅度 × 漂移全矩阵（4×6 = 24 格） | 除「幅度≤220 且漂移≥600」外全是 100% | 0% |

**按这一轮数据，结论会是「参数已经没有可拧的空间了」** —— 因为反正都是 100%。

**但这不是「真机应该测得出来」的证据。** 0.25Hz 远低于 `PPG_HP_CUTOFF_HZ = 0.5`
高通，被干干净净地滤掉了。**换成真机上更可能的漂移形态，同一幅度下结果完全不同。**

## 4. 稳健性检验：换掉「漂移是慢速正弦」这个假设（11 节）

真机的基线摆动来自呼吸 + 压力变化，是**有界随机过程**，不是纯正弦。
用一阶自回归（OU）过程替换，**幅度保持同量级**（稳态标准差 400）：

| 漂移形态 | 出数率 | 错值率 |
|---|---|---|
| 正弦 0.25Hz（= 原模型） | **100%** | 0% |
| OU，tau = 0.3 s | **46%** | **50%** |
| OU，tau = 0.8 s | 88% | 12% |
| OU，tau = 1.5 s | 100% | 0% |
| OU，tau = 3.0 s | 100% | 0% |

**决定成败的是漂移的时间尺度，不是幅度。** tau 越小（高频成分越多）越致命：
`tau = 0.3s ≈ 0.5Hz`，正好落在高通截止频率上，被「半滤」；
而 `tau ≥ 1.5s` 才被 0.5Hz 高通干净滤掉。

> **所以 §3 那张 100% 的表不能外推。** 它是「在最有利的干扰形态下」的结果。
> 这一条也是本轮最重要的方法论收获：**仿真给出 100% 时，先问「是不是我的
> 干扰模型太温柔了」，再去下「参数没问题」的结论。**

### 4.1 在随机漂移下重扫旋钮（12 节）

固定 `OU std=600, tau=0.8s`、幅度 305，基线是 **33% 出数 / 54% 错值**：

| 旋钮 | 档位 | 出数率 | 错值率 |
|---|---|---|---|
| **幅度（→ LED 电流）** | 305（7.2mA，当前） | 33% | 54% |
| | 450（≈10.6mA） | 88% | 12% |
| | **600（≈14.2mA）** | **100%** | **0%** |
| | 900（≈21.3mA） | 100% | 0% |
| 高通 | 0.5Hz（当前） | 33% | 54% |
| | 0.85Hz | 54% | 38% |
| 低通 | 4.0Hz（当前） | 33% | 54% |
| | 2.5Hz | 54% | 42% |
| 窗口 | 10s（当前） | 33% | 54% |
| | 20s | 58% | 29% |
| 一致占比门槛 | 70%（当前） | 33% | 54% |
| | 90% | 25% | **4%**（但无结果 71%） |

**四条看着都有效。而其中只有一条是真的** —— 见下一节。

## 5. 自查：把「降低低通 / 提高高通」的收益否掉（12-G）

**动机**：单级 AR(1) 的功率谱在 `f >> 1/(2π·tau)` 处**趋于平坦**。
也就是说，我造的这个「漂移」里混进了一片**宽带白噪声**。那么「降低低通」的
收益，可能只是在切这片我自己造出来的噪声，而不是真的在对抗基线摆动。

**做法**：给 OU 的输出再串一级 1.5Hz 低通（`make_ou(..., out_hz=1.5)`），
让它成为**平滑的基线摆动**。实测输出标准差从 581 降到 544 LSB
（数值量出来的，不是估的），所以这一组只能看**相对本组基线**的提升：

| 档位 | 出数率 | 错值率 | 相对基线 |
|---|---|---|---|
| 基线（幅度 305） | 75% | 21% | — |
| **幅度 450** | 96% | 4% | **+21 pp** ✅ |
| **幅度 600** | **100%** | **0%** | **+25 pp** ✅ |
| 低通 2.5Hz | **71%** | 25% | **−4 pp** ❌ 更差 |
| 低通 3.0Hz | 79% | 17% | +4 pp（噪声内） |
| 高通 0.70Hz | 75% | 21% | **0 pp** ❌ |
| 高通 0.85Hz | 75% | 17% | **0 pp** ❌ |
| 窗口 15s | 79% | 17% | +4 pp |
| 窗口 20s | 83% | 17% | +8 pp |

**读法**：
- **提高幅度**：两个漂移模型方向一致、拐点一致（600 处都到 100%）→ **可信**。
- **降低低通**：收益消失且变负 → **是模型的产物，不能落到固件**。
- **提高高通**：收益完全消失 → 同上。
- **延长窗口**：方向一致（+4~8 pp）→ 可信但小，属次级杠杆。

> **这两条的代价也不小，正好都不做**：降低低通会拿掉脉搏波的峰形（§4 弱信号
> 扫描里，低通从 4Hz 放宽到 10Hz 时错值率 0%→46%，说明低通这一档整体是承重的，
> 只能动一点点）；提高高通会伤到 `HR_MIN_BPM = 50` 的基频（0.83Hz）。

## 6. 改动：LED 电流 `0x24` → `0x4F`

### 6.1 为什么是这条

**机制（不依赖漂移形态假设）**：基线漂移与噪声是**加性**的，不随 LED 电流变化；
而脉搏波交流分量随电流**近似线性**。所以提高电流直接改善「信号/干扰」比 ——
这是它比「调滤波器」更可靠的根本原因（滤波器只是在赌干扰的频率分布）。

**换算**：`PPG_LED_PA_RED/IR` 步进 0.2mA/LSB。

| 寄存器 | 电流 | 对应扫描档 |
|---|---|---|
| `0x24`（原） | 7.2 mA | 幅度 305（= 实测 a:312） |
| **`0x4F`（新）** | **15.8 mA** | 幅度 ≈ 675 → 已过拐点 |
| `0x7F` | 25.5 mA | 幅度 ≈ 1090，d 会顶到 ≈20 万 |
| `0xFF` | 51.0 mA | d ≈ 41 万，**超 18bit 满量程 262143** |

### 6.2 为什么不是更高

`d`（红外直流）会跟着电流一起涨。实测 `d = 58234`：

| 电流 | 估算 d | 占满量程 262143 |
|---|---|---|
| 7.2 mA | 58 234 | 22% |
| **15.8 mA** | **≈ 12.8 万** | **49%** ✅ |
| 25.5 mA | ≈ 20.5 万 | 78% ⚠ |
| 51.0 mA | ≈ 41 万 | **超量程** ❌ |

超量程的后果不是「读数不准」，而是**波形被削平** —— 削平之后就没有交流分量了，
反而测不出。所以停在 `0x4F`（约 49% 利用率，仍留一半余量）。

> **自洽性检查**：`0x4F` 也正是 **docs/15 第三节早就给出的建议值** ——
> 那份文档是几个月前按手册推的，本轮扫描是从实测数据反推的，两条路走到同一个
> 数上。

### 6.3 改在哪

| 文件 | 改动 |
|---|---|
| `user/Inc/user_config.h` | `PPG_LED_PA_RED` / `PPG_LED_PA_IR`：`0x24` → `0x4F`（附完整依据注释） |
| `user/Src/max30102.c` | 注释里的「0x24 ≈ 7.2mA」改为指向 `user_config.h`，不再写死数值 |
| `docs/03-传感器接口与限制说明.md` | 值改为 `0x4F`；**顺带更正**同表里 `PPG_MIN_MODULATION` 的过期值 `0.0005` → `0.002` |

**编译**：`0 Error / 0 Warning`，尺寸与改前完全一致
（Code=46614 / RO=2094 / RW=448 / ZI=18112）—— 只改了两个宏，符合预期。

## 7. 烧录后的验收（3 步，都在 OLED 上看）

`HR_PPG_DEBUG_LINE` 默认为 1，所以第 5 行会显示 `PPG d:... a:...`：

| 步骤 | 期望 |
|---|---|
| ① 贴上手指，看第 5 行 | `d` 应从约 **5.8 万** 升到 **11 万上下**（约 2 倍） |
| ② 同一时刻看 `a` | 应从约 **3 百** 升到 **6 百上下** |
| ③ 等完 13 秒 | 第 0 行 `pending` → 出数字（或 `no pulse, retry`） |

**结果怎么读**：

| 现象 | 含义 | 下一步 |
|---|---|---|
| `d` 涨了、`a` 涨了、出数 | ✅ 改动生效 | 多测几次看出数率稳定性 |
| **`d` 涨了但 `a` 仍很低** | 有光、没搏动 —— **瓶颈在光学耦合，不在电流** | **别再调电流**，改佩戴：指腹正面压住两个小圆点、压力适中（压太紧会压瘪毛细血管）、手放桌上别悬空（docs/15 §四） |
| `d` 没涨 | 寄存器没写进去 | 查 `MAX30102_Init` 返回码 / 上电自检行 |
| 出数但值明显不对 | 可能 `d` 接近满量程被削平 | 把电流退回 `0x3A`（≈11.6mA）再试 |

## 8. 还没做 / 还没查到底的（说清楚）

### 8.1 仍然不知道「真机这次的失败是不是因为信号弱」

本轮的逻辑是：**如果**失败源于「信号不够强」，那提高电流会有帮助 —— 这一点
仿真支持得很硬。但**真机这次的失败到底是不是这个原因，还没有直接证据**，
因为决定性判据（`d` / `a`）不在云端：

| 判据 | 在哪 | 云端有吗 |
|---|---|---|
| `d` / `a` | OLED 第 5 行 | **没有** |
| 丢样本累计数 `HR_GetDroppedSamples()` | 有计数器，**但没有被显示也没有被上报** | **没有** |

所以 §7 的验收步骤是**必须做的**：它是把「仿真说应该有效」变成「真机上确实
有效」的唯一途径。如果 `d` 涨上去而出数率没变，那说明瓶颈不在信号强度上，
这一轮的改动就是无效的（但无害），方向要转到佩戴/波形形态。

### 8.2 采样链路本轮已排除，但不是「没问题」而是「没查出问题」

怀疑过「FIFO 溢出丢样本 → 锚点被反复清零 → 攒不够拍」。查下来的结论：

| 环节 | 实际值 | 结论 |
|---|---|---|
| `Sensor_Task` 周期 | `vTaskDelayUntil`（固定节拍），100ms | 不会因 DHT11/DS18B20 阻塞而漂移 |
| 采样率寄存器映射 | `spo2_sr_code(50)` → 0 = 50Hz | **配置正确**（这处曾经写死过，见 `max30102.c` 文件头） |
| 每轮样本数 | 100ms × 50Hz = 5 个 | `< PPG_BATCH_MAX = 8` → 不溢出 |

**但有一个隐性约束值得记下**：`PPG_BATCH_MAX = 8`，而 `SAMPLE_PERIOD_MS = 100`。
**若哪天把 `PPG_SAMPLE_RATE_HZ` 提到 100**，一轮就是 10 个样本 > 8 →
**每轮都丢样本** → 锚点每轮被清零（`heart_rate.c:332`）→ 窗口里攒不到拍。
这两个宏之间是有耦合的，不是各调各的。**本轮没有改任何采样参数。**

### 8.3 建议的下一步：把 `d`/`a` 与丢样本数带进报文

约 +20 字节（当前报文约 147 字节、上限 191 字节）。收益是
「心率没读数」在手机上就能分流，不必每次去盯 OLED。**要动固件所以没做。**

### 8.4 一个更根本的问题：错值率 50% 说明门槛没挡住快速漂移

§4 里 `OU tau=0.3s` 那一档，**错值率 50%** —— 即设备会给出**错误的读数**，
而 `PPG_WIN_IBI_CONSIST_PCT = 70` 没挡住它。这比「没读数」更危险。
§4 12-E 显示收紧门槛能把错值率压到 4%，代价是无结果率涨到 71%。
**这两者之间的取舍本轮没有动**（改判据的风险远高于改一个 LED 寄存器），
只把现象记在这里。
