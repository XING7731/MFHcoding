# 40 - 只让小程序告警：门限"本机生效"与"下发设备"的分离

日期：2026-09-23
触发：用户报「我无法调节阈值让微信小程序发出告警，我不需要让板子报警，只用小程序告警就行」

---

## 一、结论速览

| 问题 | 真因 | 修法 |
|---|---|---|
| 调了滑块，实时页不告警 | 滑块只改 `this.data.T`；本机 storage 要等按钮点下才更新 | 界面加 `dirty` 标志，明说"门限还没保存" |
| 唯一按钮是"下发设备"，与"不碰板子"矛盾 | 保存与下发被绑成同一个动作 | 新增「仅存本机」按钮：只写本机 storage，**一条网络请求都不发** |
| 心率/血氧从不告警 | 报文中 `hr`/`spo2` 为 `null` 时，`checkThresholds` 直接跳过 | 文档/界面说清楚（不是 bug，是"无读数不判"） |
| `cvText` 把正常用法报成故障 | 文案写死"未同步/请重新下发" | 改为同时给出两个指纹值 + 两条出路 |

**一句话**：告警判据本来就在小程序侧（`bemfa.checkThresholds` 读本机 storage），
与设备门限完全独立。用户要的能力一直都在，只是"落本机"这一步被藏在了"下发设备"按钮后面。

---

## 二、两条判据本来就是分开的（先确认这件事）

```
实时页每收到一帧 → bemfa.checkThresholds(d)
                     └─ 读 loadThresh()          ← 【本机 storage: helmet_thresh】
                     └─ 越限项 → 橙色「阈值预警」横幅

设备侧蜂鸣器     → 固件 alarm_cfg（RAM 里的那 9 项）
                     └─ 由 /set 主题下发的配置报文改写
                     └─ 受 buz 开关约束
```

两条路**没有任何耦合**。所以"只用小程序告警" = 本机门限正确 + 不下发设备。
不需要改固件，不需要加协议。

---

## 三、根因：改门限有"两步"，但界面上只给了"一步半"

改门限实际要经过：

1. `onSlide` / `onStep` / `onUseCur` → `this.render(T)` → 只更新 `this.data.T`（**界面**）
2. 点按钮 → `bemfa.saveThresh(T)` → 写 `wx.setStorageSync('helmet_thresh', T)`（**本机生效**）
3. 若点的是"下发设备"，还会额外发一条 `/va/sendMessage` 到 `<主题>/set`（**设备生效**）

第 2 步才是实时页告警的门槛。原来的界面只有"保存并下发设备"这一个按钮，
把第 2、3 步焊在一起 —— 想只做第 2 步的用户无路可走。

**诊断依据**：`tools/thresh_why.py`（本轮新增）拉设备最新帧、逐项按判据比对，得到

```
seq=48  cv=38972  t=30.0  h=44.0  gas=12  hr=null  spo2=null  st=normal   (15.6 秒前)
```

在出厂默认门限（tHi=40 / hHi=90 / gas=50 / hrLo~hrHi=50~120 / sp=90）下：
温度湿度气体全正常；**hr 与 spo2 为 null 被跳过**。所以"不告警"这个结果本身是对的 ——
真正的问题是**用户改了门限却不知道要再点一次按钮**，以及**他想告警的那两项根本没读数**。

---

## 四、改了什么

### 4.1 `pages/settings/settings.js`

- `data` 增加 `dirty: false`、`lastLocal: null`
- `render(T)` 里算 dirty：

  ```js
  const dirty = localCv !== bemfa.cfgHash(bemfa.loadThresh())
  ```

  ★ 比的是**指纹**而不是再存一份副本 —— 用同一套 `cfgHash` 判"界面 == 本机"，
  和跟设备比对用的是同一把尺子，不会出现"界面说没改、其实改了"这种口径分叉。

- 新增 `onSaveLocal()`：

  ```js
  onSaveLocal() {
    const T = this.data.T
    const bad = bemfa.validateThresh(T)
    if (bad.length) { wx.showModal({ title: '这组门限不合法', content: bad.join('；'), showCancel: false }); return }
    bemfa.saveThresh(T)
    this.setData({ dirty: false, lastLocal: { at: this.nowStr(), text: '已存到本机（未下发设备）。…' } })
    wx.showToast({ title: '已存到本机', icon: 'success' })
  }
  ```

  ★ **合法性检查先于落盘**，与 `onSend` 同一套 `validateThresh`。"整条拒绝"这条
  既有约定继续保持：越界就是整条不存，不是逐字段挑着存。

- `onSend` 成功分支清 `dirty` / `lastLocal`（下发了就不再有"未保存"这回事）
- `cmpCv` 重写：不等时不再写"请重新下发"，改为说明"若刚点过「仅存本机」这是正常的"
- 头部注释加「⚠ 改完不点按钮，门限不算改」
- `GROUPS` 的 `hint` 从"→ 蜂鸣器报警"改为"→ 判为越限"

  ★ 这一改不只是措辞：**门限的用途本来就是"判越限"，报警只是后果之一**。
  原来的 hint 把"改门限"和"设备响"绑在一起，是这次误解的界面源头。
- 心率项说明 "采集 10 秒" → "15 秒"（跟 docs/38 的窗口定档对齐，此前是漏改的）

### 4.2 `pages/settings/settings.wxml`

- 顶部加 `wx:if="{{dirty}}"` 提示框：「门限还没保存 —— 现在的改动只在这张界面上，
  实时监测页仍按上次保存的门限判读。要让新门限生效，点下面的按钮。」
- 新增第二个按钮：

  ```xml
  <view class="btn btn-secondary {{problems.length > 0 ? 'btn-off' : ''}}"
        bindtap="onSaveLocal">仅存本机（只让小程序告警）</view>
  ```

- 标题 `下发到设备` → `保存 / 下发`；`这组门限不能下发` → `不能保存`
- `蜂鸣器` → `板子蜂鸣器`，并加说明：「这个开关只管板子的蜂鸣器，管不到小程序。
  想让小程序告警、板子不响，要两件事一起做」并列出是哪两件
- 加 `wx:if="{{lastLocal}}"` 的结果块，与"已下发设备"的显示区分开

### 4.3 `app.wxss`

- 加 `.btn-secondary { background: #e6f4ea; color: #1e7a3c; }`
  （绿色 vs 主按钮的蓝色 —— 用颜色把"只动本机"和"动设备"分开）

### 4.4 `pages/index/index.js` / `index.wxml`

- `cvText(devCv)` 重写：

  ```js
  return '设备 cv=' + devCv + '，本机 ' + mine +
         ' → 两边门限不同。若你在「阈值设置」用了「仅存本机」，这是正常的；' +
         '若想两边一致，去那里点「保存并下发设备」。'
  ```

  ★ 这一处**必须改**：原文案会把人推去"反复点下发"，而那恰恰违背他"不碰板子"的意图 ——
  一个措辞不当的提示会造成反向操作，比不提示更糟。
- 横幅标题 `阈值预警（N 项）` → `阈值预警（N 项）· 小程序判定`
- `接近或超过门限的项` → `越限项`；note 说明这是小程序独立判读 + 怎么让某项立刻告警

### 4.5 `tools/thresh_why.py`（新增）

只读诊断：拉设备最新帧 → 逐项按 `checkThresholds` 的判据比对 → 三种结论分别列出
（**越限** / **正常** / **被 null 跳过**）。支持命令行覆盖门限：

```
python tools/thresh_why.py tHi=20 gas=10
```

★ 这个脚本补的是一个**一直缺失的视角**："设备报了数、门限也没错，到底哪一项该响？"
以前只能靠人对着帧手算。它对 `null` 单独分类，是因为"不做判"和"判为正常"是两件事 ——
混在一起就会出现"明明没读数、界面却说一切正常"的错觉。

## 五、验证

### 5.1 新增第 10 节（`tools/wxmp_thresh_test.js`）

★ **为什么必须单独立一节**："仅存本机"这条路径**不经过设备**。第 7/8 节的用例走的
全是下发链路，把按钮删掉它们照样全绿。所以单独立第 10 节把这条路径钉死：

```
10. 仅存本机（只让小程序告警，不下发设备）
  ok   拖滑块后界面门限变成 25
  ok   拖滑块【不】落本机（避免"改了一半"被当成已生效）
  ok   界面立刻标出"门限还没保存"（这就是"调了阈值却不告警"的现场）
  ok   「仅存本机」【一条请求都不发】—— 绝不碰设备
  ok   本机已保存新门限 25（实时页会按它判读）
  ok   保存后 dirty 灭掉
  ok   给出"已存到本机"的提示（必须与"已下发设备"能区分开）
  ok   设备 cv 仍是 38972（设备侧门限完全没变，板子不会因此报警）
  ok   两边不同时提示里带上「仅存本机」，不会把人推去反复点下发
  ok   越界门限（gas=0，下限是 1）被整条拒绝，本机那份不变
  ok   并且弹框说明为什么不能存
```

其中"**一条请求都不发**"是这一节的核心断言：`state.reqs.length` 必须不变。
它同时挡住两类回归 —— ① 有人把 `onSaveLocal` 实现成"顺手也下发一下"；
② 有人把两个按钮合并回一个。

### 5.2 第 8.2 节措辞断言改写

原断言要求 `cvText` 必须含「未同步」。但按新设计，**本机与设备不同正是"仅存本机"
要的结果，不是故障**，所以断言改成：

- 两个指纹值（48791 / 38972）都必须如实报出
- 「仅存本机」与「保存并下发设备」两种可能都要提到
- **「未同步」这个词必须不再出现**

★ 最后一条是**反向断言**。正面断言只能说"该说的说了"，反向断言才能说"武断的措辞真没了"。
这与 docs/39 里删光照时的做法同源：删掉的语义要主动断言它不存在。

## 六、被否掉的方案

### ① 让滑块松手就自动落本机（"改完即生效"）

**否掉。** 理由：

- `onSlide` 是**连续**事件。拖一次 tHi 从 10 到 40、step 是 1，会触发 30 次渲染。
  每次都写 storage，等于 30 次同步 IO；`setStorageSync` 是阻塞的，界面会明显卡顿。
- 更根本的问题是**没有"取消"这个动作**。用户在界面上试探性地拖几下、
  看看数字好不好看，本来不该改变告警行为。自动落本机意味着"手滑一下就改了报警门限"，
  而且要改回去还得记住原来是多少。
- 原先"只有点按钮才落本机"这个设计**本身是对的**，只是缺了"只存本机"这个按钮
  和一个"你还没保存"的提示。所以修法是**补按钮 + 补提示**，不是拆掉这道闸门。

### ② 把 `dirty` 存进 `data` 后在每次 `onSlide` 里重算

**否掉**，改为在 `render()` 里算。原因：`render()` 是"界面 == `this.data.T`"这个
不变量的唯一出口（settings.js 的既有设计），dirty 是 `T` 的函数，放在这里
不可能与 `T` 不同步。散到各个事件处理函数里去算，早晚会漏一处。

### ③ 让 `checkThresholds` 对 `null` 也告警（"没有读数就报异常"）

**否掉。** 理由：

- `hr`/`spo2` 为 `null` 是**常态**：没戴手指、正在采集中（`ps=1/2`）、
  或这次没测出（`ps=3`）。按 docs/15/16/35，这些都是合法状态，不是异常。
- 一旦对 null 告警，用户会在"刚戴上的头几秒"里被持续报警，然后把这一项永久性忽略 ——
  这比不报更糟，它训练用户忽略告警。
- 现在的语义（null = 不做判）是明确的，缺的只是**把这件事讲给用户听**，
  所以在界面 note 和本文档里说明，而不是改判据。

## 七、遗留 / 仍需在真机验的

- **本文档不能证明的**：巴法云 `/set` 推送是否真的到达设备、点击「保存并下发设备」
  后设备蜂鸣器是否真响。本轮只保证小程序的判读与保存行为正确。
- **用户侧仍需确认的一件事**：想让"心率过高"告警，前提是 `hr` 有读数。
  若一直 `hr=null`，那是 PPG 侧的问题（见 docs/36/38），与本轮的阈值链路无关 ——
  排查入口是屏上第 5 行 `ADC SAT d:xxxxx`。
- 旧固件（不上报 `cv`）时，`cvText` 走 `info` 分支说"无法回读"，此时**无从判断**
  设备门限与本机是否一致，但本机判读照常工作。

## 八、一句话教训

**"这个功能其实有"和"用户能找到它"是两件事。**
本次用户报的是"无法告警"，实际判据一直是好的 —— 缺的是一个按钮和一句提示。
排查顺序上，先用只读探针（`thresh_why.py`）确认"数据在、判据对"，
才能把问题范围从"判据坏了"收缩到"入口藏起来了"。
