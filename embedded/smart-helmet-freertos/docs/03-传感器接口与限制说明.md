## 二、必须由你标定的量（固件不输出未标定值）

### 2.1 血氧 SpO₂（MAX30102）

- PPG 原始数据（RED / IR）由固件完整取出。
- 由 PPG 计算 **R 值** 属于纯数学运算，固件已实现：
  `R = (AC_red/DC_red) / (AC_ir/DC_ir)`，可通过 `HR_GetRatioR()` 观察。
- **但 R → SpO₂ 的换算式含与器件、LED 电流、佩戴压力相关的系数**。这些系数不是
  公开标准值，必须在你的硬件上用**参考血氧仪同步采集**拟合。
- 因此默认 `SPO2_CAL_ENABLED = 0`：**固件上报 `"spo2": null` 并带 `"spo2_valid": 0`**，
  绝不填一个好看的数字。
- 标定步骤建议：
  1. 连续采集 30~60 秒，每秒记录一次 `R` 与参考血氧仪的读数；
  2. 覆盖高、中、低三个区间（如 88%~99%），至少三个受试者；
  3. 线性拟合得到 `SpO2 = A - B × R` 的 A、B；
  4. 填回 `user_config.h`，置 `SPO2_CAL_ENABLED = 1`。

### 2.2 光照 lux（PT0603）—— 已删除

> 🔻 **2026-09-22 起本节全部作废**。用户要求"所有光照的功能都删掉"，光照已整条
> 链路删除：`pt0603.c/.h` **文件已物理删除**，`LIGHT_*` 宏、ADC_CHANNEL_8 与 PB0
> 引脚配置、`ALARM_LIGHT_LOW`、OLED 的 `LIGHT:` 段、报文 `lux` 字段全部移除。
> 详见 `docs/39`。
>
> 下面保留原始内容，只为说明"当初为什么这么做"以及**若要加回来需要恢复什么**。

- **接口形式未确认**：需求只写了"PT0603 光照强度"，没有给出接口（模拟电压 / I²C /
  单总线）。本次实现按**模拟电压输出型**处理（ADC1_IN8 / PB0）。
- **如果你的模块是数字接口**（例如 I²C 的 BH1750 类器件），只需整体替换
  `pt0603.c` 里的 `PT0603_Init / PT0603_Read`，上层任务代码不用改。
- 模拟输出的 ADC → lux 换算需要标定。`LIGHT_CAL_ENABLED = 0` 时固件只上报 ADC
  原始值（`"light"` 是原始值、`"light_valid": 0`），并用占位阈值
  `LIGHT_DARK_RAW = 400 / LIGHT_BRIGHT_RAW = 2000` 做"光照不足"判断
  ——**这两个是占位值，必须按实测调整**。
- 标定方法：用照度计/手机照度 App 取两个照度点，记录对应 ADC 值，填入
  `LIGHT_CAL_RAW_1/LUX_1`、`LIGHT_CAL_RAW_2/LUX_2`，然后置
  `LIGHT_CAL_ENABLED = 1`，此时才使用需求给的 100 / 500 lux 阈值。
- **从未标定过** —— 这也是删掉时没有"数据损失"顾虑的原因：`LIGHT_CAL_ENABLED`
  一直为 0，上报的一直是 ADC 原始值，没有可用的物理量。

### 2.3 气体浓度（MQ-2）

- MQ-2 是模拟传感器，电压 → ppm 的换算必须在标准气体下标定。
- 固件定义的 `gas_level` 是**满量程相对百分数**：
  `gas_level = ADC原始值 × 100 / 4095`（0~100）。
  **它不是 ppm，也不是 %LEL**。需求给的阈值 50 相应地解释为"ADC 量程的 50%"。
- **预热**：气敏元件需要预热后读数才稳定，具体时间以你所购器件的数据手册为准。
  固件用 `MQ2_WARMUP_MS = 60000` 作为**占位值**（预热期内数据标记为无效、不参与
  报警判断），请按实测修改。

### 2.4 心率

- 算法是简化实现：4 秒窗口 + 直流去除 + 自适应阈值寻峰 + 峰间隔校验
  （30~200 bpm），至少 3 个合格峰间隔才输出。
- **已知局限（必须写进报告）**：
  - 运动伪影（手部晃动、佩戴松动）会造成明显失真，本版本**未做运动伪影抑制**；
  - 4 秒窗口对心率变化有滞后，不能反映瞬时心率；
  - 未做皮肤接触/佩戴检测，脱帽后可能输出不可信值（靠 `PPG_DC_MIN_RAW` 做粗过滤，
    该阈值是占位值，需按实际 ADC 量级调整）；
  - **非医疗级**，不能用于任何医学判断。
- 心率的自动报警阈值 `HR_MIN_BPM = 50 / HR_MAX_BPM = 120` 是本项目**自定义默认值**，
  不是医学标准，请按你的课题要求确定。

## 三、协议与通信的确定性说明

| 项目 | 实现方式 | 确定性来源 |
|------|----------|-----------|
| ESP01S 通信 | AT 指令（AT / AT+CWMODE / AT+CWJAP / AT+CIPMUX / AT+CIPSTART / AT+CIPSEND / AT+CIPCLOSE） | ESP-AT 通用基础指令，各版本均支持 |
| MQTT | **自实现 MQTT 3.1.1 报文**（CONNECT / PUBLISH QoS0 / PINGREQ / DISCONNECT），承载在 AT 的 TCP Socket 上 | 只依赖 TCP 相关 AT 指令，**不假设 AT 固件支持 MQTT 扩展指令**（各版本支持情况不一，无法逐一核实） |
| 未实现的 MQTT 能力 | QoS1/2、PUBACK、SUBSCRIBE、遗嘱、TLS | 明确不实现，**不声称具备加密传输或下行控制能力** |
| Broker 地址/账号 | 巴法云 `bemfa.com:9501`（明文 TCP）；鉴权用官方"方式一"——**用户私钥直接作为 Client ID，用户名/密码留空** | 巴法云官方文档 `cloud.bemfa.com/docs/src/mqtt.html` |
| WiFi 名称/密码 | `0001` / `zxc145236`（手机热点） | 用户指定；**ESP01S 只支持 2.4GHz，手机热点须切到 2.4GHz 频段** |

> 如果你要用某个云平台（阿里云 IoT / OneNET 等），需要按其要求补：
> 用户名/密码格式、topic 命名、以及可能的三元组鉴权（HMAC-SHA1 签名需要额外的
> 哈希实现，本工程未包含）。这些属于平台侧规定，请按平台文档接入。

## 四、时序与调度的确定性说明

| 项目 | 事实 |
|------|------|
| DHT11 读取 | 时序采样段（约 3~4ms）关闭中断；起始脉冲的 20ms 用 `vTaskDelay` 让出 CPU |
| DS18B20 读取 | 约 5~6ms 关闭中断；采用"发转换命令 + 1s 后取结果"两阶段，避免长阻塞 |
| 临界区内 | **只使用 TIM3 硬件计数延时**，绝不使用 `HAL_Delay()`（依赖 SysTick，会死锁） |
| OLED 刷新 | 整屏 1024 字节，400kHz 下约 25~30ms 阻塞，期间持有 I2C 互斥锁 |
| I2C 并发 | MPU6050 / MAX30102 / OLED 共用 I2C1，用 `xMutexI2C` 串行化 |
| 加速度采样率 vs 摔倒窗口 | Sensor_Task 周期 100ms → 约 10Hz。"100ms 内连续两次超阈值"实际表现为相邻两个采样点都超阈值。**若需更严格的窗口判定，应提高 MPU 采样率或使用 MPU6050 的 INT 引脚**（本版本未接 INT 引脚） |
| MPU6050 量程 | 必须 ≥ ±4g，否则 2.5g 判据会被量程削顶而永远无法满足。本工程默认 **±8g**，量程寄存器值按数据手册 AFS_SEL 编码 |
| MPU6050 未使用 DMP | DMP 需移植 InvenSense 官方驱动，体积对 64KB Flash 不划算，且可验证性差；本项目直接读原始寄存器，判据透明可复现 |
| MSP430/其他 | 不涉及 |

## 六、这份固件"不做"的事（避免过度承诺）

1. 不声称任何传感器精度、响应时间、通信时延的实测数值 —— 这些都必须在你的板子上测。
2. 不做运动伪影抑制、不做佩戴检测、不做姿态解算（无 DMP、无卡尔曼滤波）。
3. 不做数据本地存储（无 SD 卡/Flash 文件系统），断网期间的数据直接丢弃。
4. 不做远程下发控制（未实现 SUBSCRIBE）。
5. 不做低功耗管理（无 STOP/待机模式，电池续航需另行评估；需求中的
   "3.7V 电池 + 5V→3.3V 电平转换"属于电源硬件设计，不在本固件范围）。
