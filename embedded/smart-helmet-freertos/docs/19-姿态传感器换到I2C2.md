# 19 - 姿态传感器（MPU6050）换到另一条 I2C 总线

> 对应改动：`user_config.h` 新增 `MPU6050_ON_I2C2`（**当前 = 1**）；
> `main.c` 新增 `MX_I2C2_Init()` 与 PB10/PB11 的复用配置，自检屏改为**两条总线分别扫描**。
> 编译：`0 Error 0 Warning`，`Code=38950 RO=1466 RW=344 ZI=17016`（RAM ≈17.0KB / 20KB）。

---

## 一、先回答问题：可以换。但先说清楚"该不该换"

**STM32F103C8T6 上可用的硬件 I2C 只有两组：**

| 外设 | SCL | SDA | 有无重映射 |
| --- | --- | --- | --- |
| I2C1 | PB6 | PB7 | 有：可整体改到 **PB8 / PB9** |
| **I2C2** | **PB10** | **PB11** | **无**（只能是这两个脚） |

本工程当前的引脚占用（`user_config.h` 的分配表）：

| 已被占用 | 用途 |
| --- | --- |
| PA1 / PB12 / PA4 / PB5 | DHT11 / DS18B20 / SOS 按键 / 蜂鸣器 |
| PB0 / PB1 | ~~PT0603(ADC1_IN8) /~~ MQ-2(ADC1_IN9) —— PB0 已于 2026-09-22 随光照功能删除（`docs/39`） |
| PB6 / PB7 | I2C1：OLED + MAX30102 |
| PA9 / PA10、PA2 / PA3 | USART1(ESP01S) / USART2(调试) |
| PA13 / PA14 | SWD，**不可占用** |

所以 **PB10 / PB11 本来就是空闲的**，拿来做 I2C2 不需要让任何东西。

### 但"三个器件共用一对引脚"本身不是错误

I2C 是**总线**：OLED(0x3C)、MPU6050(0x68)、MAX30102(0x57) 并联在 PB6+PB7 上，靠**从机地址**区分，主机"点名"通信，未被点名的器件保持沉默。**共用完全能正常工作，不需要片选线。**

真正值得换的理由只有这三条：

1. **抗"单器件拖死总线"**——某个器件故障把 SDA 拉死在低电平时，整条总线会一起瘫痪，现象是"**连 OLED 也黑屏**"，看起来极像引脚打架。分开后 MPU6050 挂死不会再连累屏幕和心率；
2. **想单独盯姿态数据流**——OLED 每 2 秒整屏刷一次（连续几百字节），把姿态数据夹在同一对线上，用逻辑分析仪看会比较吵；
3. **走线方便**——MPU6050 装在帽子顶部、离主板较远时，与屏幕分开走线更省事。

如果这三条都不成立，**保持共用（`MPU6050_ON_I2C2 = 0`）即可**，功能上没有损失。

## 二、方案对比

| 方案 | 引脚 | 需要改什么 | 适合场景 |
| --- | --- | --- | --- |
| **A（当前采用）** | I2C2：PB10 / PB11 | 挪 3 根线 + 宏 = 1 | **推荐**。只动 MPU6050，OLED/心率不受影响 |
| B | I2C1 重映射到 PB8 / PB9 | 挪 3 个模块的全部 SCL/SDA | 若你想把**整条 I2C1** 换地方（比如 PB6/PB7 要挪作他用） |
| C | 任意两个空闲脚 + 软件模拟 I2C | 新写一套 bit-bang 驱动 | **不建议**。400kHz 下 CPU 开销大、时序易受中断影响，而硬件 I2C2 是免费的 |

**方案 B 为什么不顺手**：I2C1 上还挂着 OLED 和 MAX30102，重映射会把它们**一起搬走**（I2C 的重映射是整条外设的，不能只搬家一个器件）。所以想让"MPU6050 单独一条线"，用 I2C2 最省事。

**方案 C 补充**：如果以后确实需要非 I2C 引脚的组合，软件模拟是唯一出路。本工程的 `bsp_delay.c` 已提供 `delay_us()`（TIM3 1MHz 基准），具备实现条件；但要注意 DHT11/DS18B20 的时序段会关中断 4~6ms，bit-bang 期间遇到会被拉长，需要做重试。

## 三、硬件怎么改（3 根线）

| MPU6050 引脚 | 从（共用） | 改为（I2C2） |
| --- | --- | --- |
| SCL | PB6 | **PB10** |
| SDA | PB7 | **PB11** |
| VCC / GND | 3.3V / GND | **不变** |
| AD0 | GND | **不变**（地址仍是 0x68） |
| INT / XDA / XCL | 悬空 | **不变**（固件轮询，不用中断） |

**两点注意：**

- **上拉电阻**：I2C2 是**独立的一条线**，仍需一组 4.7K 上拉到 3.3V。GY-521 类模块板载自带，**不要再叠加**。SDA/SCL 的上拉**不能与 I2C1 共用**（两条线是独立的网络）。
- **PB10 / PB11 不再空闲**：`MPU6050_ON_I2C2 = 1` 时它们被配置为 I2C2 复用开漏，别在它们上面再挂别的信号。

## 四、软件怎么改（一个宏）

`user/Inc/user_config.h`：

```c
#define MPU6050_ON_I2C2       1   /* 1 = MPU6050 独占 I2C2 (PB10/PB11)
                                     0 = 与 OLED/MAX30102 共用 I2C1 (PB6/PB7) */
```

代码层面已经收敛好了，**只需要改这一个宏**：

- `main.c` 用 `MPU6050_HI2C` 宏选句柄（`&hi2c2` 或 `&hi2c1`），`MPU6050_Init()` 只在这一处绑定；
- `mpu6050.c` 驱动本身只用构造时传入的句柄（内部 `s_i2c`），**一行都不用改**；
- `app_tasks.c` 的 `MPU6050_Read()` 不需要句柄参数，**也不用改**；
- `xMutexI2C` 这把锁**保持原样**：它统一保护所有 I2C 访问，MPU6050 在 I2C2 上仍持有它。多包一层只是把两条总线串行化，单锁顺序获取**不可能死锁**，功能安全。

**两种配置都已实测编译通过：**

| 配置 | 结果 |
| --- | --- |
| `MPU6050_ON_I2C2 = 1` | 0 Error 0 Warning，`Code=38950 RO=1466 RW=344 ZI=17016` |
| `MPU6050_ON_I2C2 = 0` | 0 Error 0 Warning，`Code=38690 RO=1466 RW=336 ZI=16928`（体积回到原值，说明**没有任何多余代码**残留） |

## 五、上电自检屏（判断接对没有）

固件上电后会把**两条总线分别扫一遍**，并按引脚标注写屏，停留约 3.5 秒：

```
SMART HELMET
I2C1 PB6/7: 3C 57        ← OLED(3C) 与心率(57) 应在这里
I2C2 PB10/11: 68         ← MPU6050(68) 应在这里
O:OK M:OK X:OK           ← 三个器件是否都在线
MAX30102 OK
```

**判读表：**

| 屏幕 | 含义 | 处理 |
| --- | --- | --- |
| `I2C2 PB10/11: 68` + `M:OK` | 姿态传感器已在独立总线上，**换线成功** | 完成 |
| `I2C2 PB10/11: none` + `M:--` | I2C2 上一个器件都没应答 | 线还接在 PB6/PB7 没挪过来（最常见），或 PB10/PB11 接触不良、没供电、缺上拉 |
| `I2C1 PB6/7: 3C 57 68` | MPU6050 还挂在 I2C1 上 | 硬件还停在旧接法（固件已按 I2C2 找它），把 SCL/SDA 挪到 PB10/PB11 |
| `I2C2: off` | 本工程未启用 I2C2 | 说明 `MPU6050_ON_I2C2 = 0`，此时 MPU6050 应在 `I2C1` 那一行里 |

> **为什么要把引脚直接写屏**：这类改动一旦硬件和软件**不同步**（线挪了固件没改，或反过来），表现都是"某个器件读不到"，而屏幕上一串十六进制地址是看不出问题在哪的。把 `PB6/7` 与 `PB10/11` 标在对应地址前面，一眼就能和手上的接线对上。
>
> **`M:OK` 的判据是跟着宏走的**：固件去"MPU6050 应该在的那条总线"上找 0x68。若换了总线却仍去旧总线找人，屏幕会一直显示 `M:--`，反而让人怀疑模块坏了——这正是本项目反复踩过的误判来源。

## 六、注意事项

1. **硬件与软件必须同步**。最常见的错误是只做了其中一半，然后看到"姿态读不到"就往传感器上找原因。
2. **PB10/PB11 的复用配置在 `HAL_I2C_MspInit()` 里**：`__HAL_RCC_I2C2_CLK_ENABLE()` + PB10/PB11 配 `GPIO_MODE_AF_OD`。I2C2 无需 AFIO 重映射。
3. **两条总线都在 APB1（36MHz）**，400kHz 时序没有差别，MPU6050 支持快速模式。
4. **换总线不改变器件地址**（AD0 仍接 GND → 0x68）。地址不对时会显示 `M:--` 或初始化返回 ID 错。
5. **不影响其它功能**：OLED、心率、联网、上报链路都与本次改动无关，不需要重新标定任何参数。
