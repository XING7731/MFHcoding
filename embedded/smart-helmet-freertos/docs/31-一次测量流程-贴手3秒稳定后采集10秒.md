# 31 · 一次测量：贴手 → 稳定 3 秒 → 采集 10 秒 → 出最终结果

> 触发问题（用户原话）：
> **"应该是检测到手放在传感器上 3 秒后，开始检测 10 秒，用这 10 秒的数据计算心率和
> 血氧，10 秒结束显示最终结果，检测时 oled 上显示 pending"**
>
> 这不是"再调个参数"，而是**把测量流程从"持续测量"改成"一次测量"**：
> 从"稳定期一过就每拍刷新一个数"改成"只在一个 10 秒窗口结束时给出一个冻结的值"。
>
> 改流程会牵动三处：算法怎么算（一份数据 vs 最近 3 拍）、什么时候发布
> （屏上 pending / 上行 null）、什么时候作废（拿开手指 = 整次作废）。
> 这一篇把三处都讲清楚，并且**两处被自己的仿真打脸的地方也如实写下来**（§8）。

---

## 1. 一句话结论

| | 旧版（docs/30） | 本版 |
|---|---|---|
| 流程 | 贴上 → 稳定 3s → **持续输出**（每拍重算） | 贴上 → 稳定 3s → **采集 10s** → 出结果并**冻结** |
| 算法 | 最近 **3 拍** IBI 的中位数 | 窗口内**全部合格拍**的中位数 + **一致占比门槛** |
| 屏上 | `PPG ready R:0.72` + 一直在变的数 | `PPG: pending 7s` → `PPG: done R:0.72` |
| 上行 | 稳定期一过就有 hr | 采集期 hr=null + `ps` 字段说明在忙还是没测到 |
| 拿开手指 | 0.8s 后回到 IDLE | 同左，且**采到一半拿开 = 整次作废**（不给半个窗口的结果） |
| 陈旧值 | 靠 `PPG_HR_STALE_MS` 超时作废 | **结构上不存在** —— 采完冻结、拿开清零，超时判据已删除 |

**核心收益（有实测数据，不是设计意图）**：同一段弱信号波形跑 6 个噪声 realization，
旧版 6 次里有 **2 次**报出 **115 / 130 bpm（真值 72）**；新版**一次偏差 > 5 bpm 的都没有** ——
不能确定的那 3 次它明确报"没测到"。**把"不知道"变成"知道"**（§4.3）。

## 2. 流程与状态机

```
贴上手指
   │  300ms 去抖(PPG_CONTACT_ON_MS)
   ▼
SETTLING    3s   屏上: PPG: settling in 3..1s     上行 hr: null
   │              (算法照跑: 滤波预热/窗口填充/峰值参考跟踪, 但【不采集】)
   ▼
MEASURING   10s  屏上: PPG: pending 10..1s        上行 hr: null
   │              (每拍往窗口里累计 1 个 IBI + 1 个 R)
   ▼
DONE        ——   屏上: PPG: done  R:0.72          上行 hr: 最终值(冻结)

任意时刻连续 800ms 检测不到手指 → 整次作废, 回到 IDLE, 屏上回到 put finger on
```

实测时间线（`tools/ppg_measure_sim.py` §1）：

| 状态 | 进入时刻（贴手后） | 段长 |
|---|---|---|
| SETTLING | +280 ms | 3000 ms |
| MEASURING | +3280 ms | 10000 ms |
| DONE | +13280 ms | 冻结至拿开手指 |

四个状态都在 `HR_State_t` 里，**发布门控做在 `HR_GetResult()`**（不在显示层）——
屏上和云端走同一个出口，不会出现"屏上还在 pending、云端已经收到一个数"。

## 3. 为什么改成有限窗口

1. **持续测量时"稳了没有"无法判断**。屏上的数每 2 秒变一次（其实每拍都在重算），
   用户看到的是一个会动的数，没法判断能不能采信 —— 这正是"读数随机"的观感来源。
2. **10 秒能拿到足够多的票**。60~100bpm 下窗口内有 10~16 个 IBI，用整段的中位数，
   一次伪影拖不走结果；旧版只有最近 3 拍投票，噪声伪造一拍就能带偏 10bpm 以上。
3. **有限窗口让"陈旧值"在结构上消失**。采完就冻结、拿开就清零，
   `PPG_HR_STALE_MS` 那条超时判据成了冗余 —— **已删除**。
   同一件事留两个判据，出问题时要同时怀疑两个地方，不如删掉一个。
4. **它给了一个明确的"可以信"的时刻**。`pending` 倒计时归零 = 结果有效，
   用户不用猜；测量失败时屏上明确写 `no pulse, retry`，而不是让人对着 `HR:--` 干等。

## 4. 算法：从"最近 3 拍"到"整段中位数"

### 4.1 窗口里累计什么

| 量 | 来源 | 窗口结束时怎么用 |
|---|---|---|
| IBI（相邻两拍间隔，ms） | 每检出一个峰、通过不应期与生理范围检查后追加一个 | 取**中位数** → `HR = 60000 / IBI` |
| R（血氧比值） | 每个峰时刻用 4 秒滑动窗口算一次 `(AC_red/DC_red)/(AC_ir/DC_ir)` | 取**中位数** → 换算式 → SpO2 |

窗口上限 `PPG_WIN_MAX = 40`（10 秒 @200bpm 最多 33 拍）。
两者都只在 `MEASURING` 期间增长；进入 `SETTLING` 时 `begin_settle()` 已清过一次，
所以窗口起点必然是空的（不会把上一次次测量的拍混进来 —— 实测见 §7 场景五）。

### 4.2 一致占比门槛 `PPG_WIN_IBI_CONSIST_PCT`

**中位数能挡住少数离群点，但挡不住"系统性双峰"。**

信号弱（调制比 0.3%）而基线漂移比脉搏波还大时，一个心搏会被顶出**两个**局部极大值，
检出的间隔就变成 `500, 1000, 500, 1000...` 的双峰分布 —— 而**中位数正好落在两峰之间**，
给不出明显的错值。这是仿真查出来的（§8 ②），不是设计时想到的。

判据：与中位数相差不超过 `PPG_IBI_TOL_PCT`（25%）的拍数，要
① 不少于 `PPG_WIN_IBI_MIN`（3）拍，且
② 占总拍数的 `PPG_WIN_IBI_CONSIST_PCT`（70%）以上。
不满足 → **不给结果**，屏上 `no pulse, retry`。

取 70 的依据：干净信号实测一致占比 **100%**（50/72/90/110 四个心率都是），
被打掉的两次分别是 **0%** 和 **67%** —— 门槛放在 70 既不误伤正常信号，又能挡住双峰。

### 4.3 实测对照（同一段弱信号波形，6 个噪声 realization）

| seed | 旧版给出的读数（稳定期后） | 偏差 | 新版 |
|---|---|---|---|
| 31 | `[68, 73, 75]` | 4 | 不给结果（no pulse, retry） |
| 61 | `[73]` | 1 | 73 bpm（+1） |
| 62 | `[111, 130]` | **58** | 不给结果 |
| 63 | `[73, 75, 77]` | 5 | 75 bpm（+3） |
| 64 | `[71, 73, 115]` | **43** | 不给结果 |
| 65 | `[73, 75]` | 3 | 73 bpm（+1） |

**统计：旧版 2/6 次报出偏差 > 10 bpm 的读数；新版 0/6 次偏差 > 5，3/6 次明确说没测到。**

> 顺带一个诚实的观察：**干净波形下旧版也不跳**（实测稳定在 71）。
> 所以"读数随机"的现场不在干净波形上，而在**信号弱 + 漂移大**的时候 ——
> 那正是贴不紧、末梢循环差的常态。

### 4.4 血氧跟着心率一起门控

`finish_measure()` 里，血氧只在**心率通过门槛**时才算：同一个窗口、同一段信号，
不会出现"心率不可信而血氧可信"（两者都受双峰伪影影响，血氧还会被运动伪影直接带偏）。
屏上本来也是"没有心率就不显示血氧"，两处现在一致了。

## 5. OLED：行0 的四种状态 + 行5 新增 `b:`

```
第1行  PPG 测量状态(put finger on / settling in 3s / pending 7s / done)  ← 唯一改动处
第2行  HR:72 SpO2:94%~        心率/血氧
第3行  T:26.5C H:58%          温度/湿度
第4行  GAS:120               气体（2026-09-22 起 LIGHT 段已删除，见 `docs/39`）
第5行  A:0.0 0.1 1.0|1.0      三轴加速度 + |a|
第6行  状态(报警 / 传感器异常 / 摔倒瞬时态 / PPG 中间量 d:/a:/b:)
第7行  UP:00:12:34 P1.0       运行时长 + |a| 峰值
第8行  NET: OK p=26 e=26      联网诊断
```

行0 五档：

| 显示 | 含义 |
|---|---|
| `PPG: sensor NG` | 芯片不在 I2C 总线上 → 转 `docs/14` |
| `PPG: warming up` | 在线上，预热样本没攒够 |
| `PPG: put finger on` | 未检测到手指 → 第2行 `HR:--` 是**正常**的 |
| `PPG: settling in 2s` | 稳定期倒计时 → 没数**也是正常的** |
| `PPG: pending 7s` | **采集中，还剩 7 秒**（用户要求显示 pending，这里连秒数一起给） |
| `PPG: done  R:0.72` | 测完了，结果在第2行；顺便常显 R 值（血氧标定要记的就是它） |
| `PPG: no pulse, retry` | 采完了但没攒够合格拍数 → **明确说没测到**，不是还在忙 |

**为什么 pending 要带秒数**：一个光秃秃的 `pending` 不告诉人还要等多久，
而 10 秒不说话很容易被当成死机。向上取整，所以显示归零的那一刻**正好**是出结果的那一刻。

**行5 新增 `b:`（窗口内已攒到的合格拍数）**：`d:50123 a:612 b:12`。
pending 期间看它有没有在涨，就知道这次测量有没有希望（一直不涨可以直接重贴，不必干等 10 秒）；
测量失败后它说明"只攒到 2 拍"。
为放得下，这两个变体去掉了 `PPG ` 前缀 —— 因为截断会把 `b:12` 显示成 `b:1`，
那是个**看起来正常但是错的**读数，比不显示更糟。

## 6. 上行报文：新增 `ppg_state`

一次测量有 **13 秒**（3 秒稳定 + 10 秒采集）上行 `hr` 是 `null`。
不带状态字段的话，收数据的人无法区分"没放手"、"正在测"、"测了没测到" ——
这三种处置完全不同。

```diff
  {"ts":"10:45:58","seq":26,"hr":null,"spo2":null,"sc":0,
+  "ps":2,
   "t":26.5, ...}
```

| 值 | 状态 | 该做什么 |
|---|---|---|
| 0 | 没检测到手指 | 提示用户贴手指 |
| 1 | 稳定中（3s） | 等一下 |
| 2 | 采集中（pending 10s） | 等一下 |
| 3 | 测量完成 | `hr` 有效则采用；`null` 则是"没测到"，可提示重测 |

精简格式是 `"ps"`，完整格式是 `"ppg_state"`（两者都加了）。
这是**回应 docs/30 §9.3 留的那个口子** —— 当时说"需要区分的话说一声，加上很快"。

## 8. 两处被仿真打脸的地方（如实记录）

### ① "贴手那一次阶跃靠吸附挡住" —— 站不住

docs/30 §4 的结论是：阶跃吸附（`PPG_DC_STEP_FRAC`）挡的是**贴手瞬间**的阶跃。
本轮仿真发现：**那一次并不需要它。**

原因是去抖 300ms 后 `begin_settle()` 会**清算法 + 把直流估计锚到当前样本**，
之前冲出来的假峰、连同被顶高的峰值参考**一起被丢弃**。
实测：去掉吸附，贴手场景照样测出 71 bpm。

**那吸附还有用吗？有，但它管的是另一段** —— **测量过程中**的阶跃
（手指挪动、按压力度变化）。这一次没有"清算法重来"的机会：

| 变体 | 阶跃后峰值参考 | 窗口内合格拍数 | 结果 |
|---|---|---|---|
| 去掉吸附 | **36385**（脉搏波的 **60.6 倍**） | 7 拍 | 71 bpm |
| 有吸附 | **574**（1.0 倍） | 12 拍 | 71 bpm |

阈值被抬到真搏动之上后，只能靠"连续 6 秒没峰就减半"的逃生通道往回爬 ——
而采集窗口只有 10 秒，等不起。**所以这条代码保留，但注释已按实测改写**
（`user/Src/heart_rate.c` 的 `bandpass()`、`user_config.h` 的 `PPG_DC_STEP_FRAC`）。

### ② "中位数就够了" —— 不够

见 §4.2。中位数挡不住双峰，必须配一致占比门槛。这条门槛是**仿真查出来的**，
不是设计出来的；没有它，第六节那三个弱信号场景里有一个会报出 94 bpm 的错数。

> 这两条说明一件事：**上一版的结论要能被下一版的仿真推翻，才叫证据。**
> `tools/ppg_contact_sim.py` 里"阶跃吸附的必要性"那段论证现在已被推翻，
> 脚本头部加了版本对应说明（它对应的是 09-17 上午版固件），结论以本篇为准。

## 9. 烧录后验收（6 步，全在 OLED 上看）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 上电，**不碰传感器** | 第1行 `PPG: put finger on`；第2行 `HR:-- SpO2:--` |
| 2 | 食指轻盖光学窗口，**保持不动** | 第1行 `PPG: settling in 3s`，**3 → 2 → 1** |
| 3 | 倒计时归零 | 第1行变成 `PPG: pending 10s`，**10 → 9 → … → 1** |
| 4 | 倒计时归零 | 第1行 `PPG: done  R:0.7x`；第2行出现 `HR:7x SpO2:9x%~` |
| 5 | 手指继续不动 | 读数**不再变化**（这就是"最终结果"） |
| 6 | 移开手指 | 约 0.8 秒内第1行回到 `put finger on`，第2行回到 `HR:--` |

**若第4步出现 `PPG: no pulse, retry`** —— 这次没测到，重新贴一次。
先看第6行的 `b:`：

| 第6行 | 判断 |
|---|---|
| `d≈0` | 压根没采到光 → LED 没亮 / 没盖住光学窗口 / 模块异常 |
| `d` 正常、`a≈0` | 有光但**没有脉搏波** → 贴合不好 / 压力过大 |
| `d`、`a` 正常、`b` 不涨 | 阈值被一次扰动顶住了 → 保持手指不动，或重贴一次 |
| `b` 涨到了 ≥3 但仍报没测到 | 拍与拍之间**不一致**（一致占比 < 70%）→ 信号质量差，重贴或按压适度 |
| 末尾 `DRP` | FIFO 溢出丢样本 → 查 I2C 读取节奏（见 docs/29） |

**第1行一直是 `put finger on`（贴了但没识别）**：IR 原始值没超过
`PPG_CONTACT_RAW_TH = 2000`，此时第6行的 `d` 会是几百 —— 属于**光学/结构问题**
（窗口脏了、模块没对准），不是算法问题。

## 10. 已知取舍（如实记录）

1. **一次测量给的是"这 10 秒的平均心率"**，不是瞬时值，也不反映 10 秒内的心率变化。
   要做连续监测心率变化，需要另加一个"滑动窗口"模式 —— 那不是本轮的需求。
   论文里写"心率"时要注明这是窗口均值。
2. **结果会一直挂着，直到手指拿开**。这不是 bug（是"冻结"的定义），
   但用户如果一直贴着不拿开，看到的会是 13 秒前那次测量的结果。
   想要"每 N 秒自动重测"的话，只要在 `DONE` 状态里加一个计时器回到 `SETTLING` 即可
   （本轮刻意没做：那是另一条没被仿真覆盖的路径）。
3. **采集期任何一次拿开手指都会整次作废**（去抖 800ms）。手指大幅挪动会白白丢掉
   已经采集的 10 秒，需要重来 —— 这是"宁可重来，也不要半个窗口的结果"的取舍。
4. **13 秒等待是这套设计固有代价**。想缩短就把 `PPG_MEASURE_MS` 调小，
   但要接受"票数变少、抗伪影能力下降"（10 秒 → 5 秒，票数从 12 降到 6）。
5. **拿开后约 0.8 秒内仍显示最后一个数**（`PPG_CONTACT_OFF_MS` 去抖，沿用 docs/30 的取舍）。
6. **弱信号下"不给结果"的比例不低**（实测 6 次里 3 次）。这是刻意的：
   这个设计选择的是"宁可让人重测，也不要给一个看起来很正常的错数"。
   如果演示时希望"总有数出来"，把 `PPG_WIN_IBI_CONSIST_PCT` 调低（如 50）即可，
   代价是那两次 115/130 会重新出现。
7. **运动伪影仍未解决**（同 docs/03、docs/30）。
