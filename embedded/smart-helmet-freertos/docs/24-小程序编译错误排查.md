# 24. 小程序「编译错误」排查 —— 工具的编译缓存与磁盘不一致

> 现象是"编译错误"，真因是**开发者工具的缓存停在旧状态**：它仍在编译
> 一个**已经被删除**的模板页面 `pages/logs/logs.wxml`。
> 工程代码本身没有任何问题。

---

## 1. 结论先行

| 项 | 结论 |
|---|---|
| 工程代码 | **没问题**。16 个源文件逐项静态校验全通过（见 §5 的预检脚本） |
| 真正的报错 | `ENOENT: no such file or directory, open '...\pages\logs\logs.wxml'` |
| 病因 | 开发者工具内部仍持有**含 `pages/logs` 的旧 app.json 解析结果** |
| 修法 | 清缓存 / 关闭项目重开（见 §4） |

---

## 2. 现场证据

### 2.1 工具日志里的原话

路径：`%LOCALAPPDATA%\微信开发者工具\User Data\<hash>\WeappLog\logs\`

```
[09:29:14][ERROR][appservice] simulator launch catch error
  Error: app.json: 未找到 ["pages"][1] 对应的 pages/trend/trend.wxml 文件

[09:31:06][ERROR] updateAppCode pages/trend/trend.wxml
  Error: Couldn't find the module of the file (pages/trend/trend.wxml)

[10:13:58][ERROR][PROJECT] [devtools] webview on error
  Error: 编译 .wxml 文件错误，错误信息如上，可在控制台查看更详细信息
  ENOENT: no such file or directory, open
    'C:\Users\27362\Desktop\WeChat smart helmet\pages\logs\logs.wxml'
```

### 2.2 时间线对照（决定了哪条是"真问题"）

| 时刻 | 事件 | 判断 |
|---|---|---|
| 09:29:14 | `app.json` 写盘（注册 index + trend） | — |
| 09:29:14 ~ 09:30:22 | 工具反复报"未找到 `pages/trend/trend.wxml`" | **过期**：当时该文件确实还没生成 |
| 09:31:03 / 09:31:06 / 09:31:13 | `trend.js / .wxml / .wxss` 依次写盘 | 文件是分 3 次落盘的 |
| 09:31:06 / 09:31:13 | 工具报 `Couldn't find the module` | **过期**：文件刚落盘时的增量更新报错 |
| **10:13:52 / 10:13:58 / 10:16:06** | 仍报 `ENOENT ... pages/logs/logs.wxml` | **★ 当前的真问题** |

关键点：
- `app.json` 在 **09:29:14** 之后**再没改过**，那时它就已经不含 `pages/logs` 了。
- 磁盘上**搜不到任何** `logs` 引用（`grep -rn logs .` 为空）。
- 但工具在 **10:16:06**（本文件 mtime 刷新后 3 秒）**依然**去编译 `pages/logs/logs.wxml`。

⇒ 工具**看得到**文件变化（它触发了编译），**但它的 app.json 解析结果没更新**。

### 2.3 预热 5 秒的模型

开发者工具是"长驻进程 + 增量编译"：

```
磁盘文件 ──文件监听──▶ 工具的模块图 ──▶ 模拟器(appservice/webview)
              ↑                ↑
         这一步经常漏      一旦漏了，后面一直用旧图
```

`pages/logs/` 是在工具有效运行期间被**外部程序删除**的。文件监听没有把这个
"删除"告诉模块图，于是模块图里 `pages/logs` 一直还在 → 每次编译都去打开它 → ENOENT。

## 3. 为什么"改了代码怎么都不生效"

这类缓存不一致的典型表现，遇到任意一条基本可以确诊：

- 文件明明在，却报"未找到 xxx 文件"
- 报错指向一个**已经被删掉**的文件（ENOENT）
- 改代码后一切照旧，像没保存一样
- 报错里的页面/组件是**上一版**的结构

它们的共同点：**报错内容描述的是一个已经不存在于磁盘的状态。**

> 判据：把报错里提到的那个路径**拿去磁盘上找**。
> 找不到 ⇒ 一定是工具的缓存问题，不是你代码的问题。

---

## 4. 怎么修（按顺序，第一步通常就够）

### 4.1 清缓存

```
开发者工具菜单 →「工具」→「清缓存」→「清除全部缓存」
```

或快捷键 `Ctrl + Shift + Delete`（部分版本），勾选"清除全部缓存"后重新编译。

### 4.2 关闭项目重新打开

清缓存**不重启**时，工具内存里的 builder 实例可能仍是旧的
（日志里 `[BuilderFactory] ... shouldCreate=false` 就是复用了旧实例）。
所以如果 4.1 没解决：

```
右上角「项目」→「关闭项目」→ 重新打开该项目
```

或者直接**退出开发者工具再启动**。

### 4.3 命令行方式（需要先在工具里开启"服务端口"）

```bat
:: 只清编译缓存，不动本地数据/登录态
"C:\apps\weixinyunpingtai\微信web开发者工具\cli.bat" cache --clean compile ^
  --project "C:\Users\27362\Desktop\WeChat smart helmet"
```

`--clean` 的可选值：`storage | file | compile | auth | network | session | all`。
**`compile` 是最安全的一档** —— 不碰小程序本地数据、不碰登录态。

前提：`设置 → 安全设置 → 服务端口` 必须为**开启**状态，否则 CLI 会直接报
`IDE service port disabled`。

### 4.4 如果以上都无效

把工程**复制到不含空格的路径**下重新导入，例如：

```
C:\Users\27362\Desktop\WeChat smart helmet     ← 含空格
C:\Users\27362\Desktop\wechat-smart-helmet     ← 更稳
```

日志里出现过 `[DevtoolsFileWatcher] c:/Users/27362/Desktop/WeChat smart helmet false`
—— 结构含空格的路径上，文件监听容易失效，这是这类缓存不一致的常见诱因。

## 5. 自查工具：`tools/wxmp_precheck.js`

不依赖开发者工具，**只读磁盘**，独立复现微信编译期的硬性检查。

```bash
node tools/wxmp_precheck.js "C:\Users\27362\Desktop\WeChat smart helmet"
```

桌面已放好双击入口：**`小程序工程预检.bat`**（也可把工程文件夹拖到它上面）。

它检查 7 组共 23 项：

| # | 检查内容 |
|---|---|
| 1 | 工程骨架、app.json 是否带 BOM |
| 2 | **app.json 注册的每个页面，.js/.wxml 是否都在**（就是工具报的那类错） |
| 3 | tabBar.pagePath 是否已注册、iconPath 是否存在、自定义组件路径是否存在 |
| 4 | WXML 标签配对、`{{}}` 里是否用了可选链/模板串等被禁语法、`wx:for` 缺 `wx:key`、未注册组件 |
| 5 | WXSS 大括号配对、BOM、通配符选择器 |
| 6 | JS 语法（V8 解析）+ `require` 相对路径是否存在 |
| 7 | **翻开发者工具日志，把最近报的错原文打出来，并自动判读"哪个文件已不在磁盘上"** |

第 7 项是它最有用的地方 —— 工具界面只给一句"编译错误"，
真正的 `ENOENT xxx` 只在日志里；脚本把它捞出来并直接告诉你是哪一侧的问题。

另有 **文件名大小写检查**：Windows 不区分大小写，但小程序上传到服务器后区分。
`pages/Index/index` 这种写法本地永远正常、上传后必挂，脚本会拦下来。

---

## 6. 顺带修掉的一处配置问题

`project.private.config.json` 里 `urlCheck: true` **覆盖**了
`project.config.json` 的 `false`（工具生成的私有配置优先级更高）。

它的含义是"**在开发者工具里也校验请求域名**"。影响：

- 真机 / 体验版：不受影响（域名由微信后台校验）
- **开发者工具内**：会被拦，请求直接失败 → 表现为"获取数据失败"

已改为 `false`。这样工具内的"一键连接诊断"才能真正测到**网络层**，
而不是被工具自己挡在前面、报一个"域名不在白名单"的假象。

## 7. 判据速查表（下次直接用）

| 症状 | 病因 | 处理 |
|---|---|---|
| 报错指向**已删除**的文件（ENOENT） | 工具缓存旧状态 | 清缓存 / 关项目重开 |
| 报"未找到 xxx 文件"，但文件确实在 | 同上 | 同上 |
| 改代码完全没效果 | 同上 | 同上 |
| 预检脚本第 2 节报"页面缺文件" | **真·代码问题** | 补文件或改 app.json |
| 预检脚本报 `app.json 带 BOM` | 真·代码问题 | 另存为无 BOM 的 UTF-8 |
| 工具内报域名不在白名单 | `urlCheck` 为 true | 改 false（或配好工具内域名） |
| 真机报域名不在白名单 | 微信后台的服务器域名没配 | 公众平台配置 |
