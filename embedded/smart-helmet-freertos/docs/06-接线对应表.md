**I2C 分成两条总线（2026-09-14 起）**：

- **I2C1（PB6 + PB7）**：OLED(0x3C) / MAX30102(0x57) —— 两者并联，靠从机地址区分，不需要片选线；
- **I2C2（PB10 + PB11）**：MPU6050(0x68) —— 姿态传感器单独占一条总线。

把姿态传感器分出去的目的是**抗"单器件拖死总线"**：任一器件故障把 SDA 拉死在低电平时，
整条总线会一起瘫痪（现象是"连 OLED 也黑屏"，看起来像引脚打架），分开后 MPU6050 挂死
不会再连累屏幕和心率。

> 这条分工由 `user_config.h` 的 **`MPU6050_ON_I2C2`** 决定，**当前为 `1`（走 I2C2）**。
> 置 `0` 即回到"三者共用 I2C1（PB6/PB7）"——**此时必须把 MPU6050 的 SCL/SDA 接回 PB6/PB7**。
> 硬件与软件这两个动作必须同步，只改一头的结果就是"姿态传感器读不到"。
> 上电自检屏会分别列出两条总线扫到的地址及对应引脚，接错一眼可见。

> **"心率传感器和 OLED 用了同一个引脚"不是冲突** —— 这是 I2C 的既定用法。
> 固件上电时会扫一遍总线并把结果写屏（`O:OK M:OK X:OK`），按复位键即可确认
> 三个器件是否都在线。原理、接线细节与判读表见
> **`docs/14-I2C共用总线与心率模块接线.md`**，换总线的完整说明见
> **`docs/19-姿态传感器换到I2C2.md`**。

## 三、电源分配（这一节不看会踩最大的坑）

```
3.7V 锂电池
   │
   ├─→ 【5V 升压模块】──────→ MQ-2 的 VCC（加热丝需要 5V）
   │
   └─→ 【3.3V 稳压 LDO / DC-DC】
            │
            ├─→ STM32F103C8T6  (VDD/VBAT)
            ├─→ DHT11、DS18B20
            ├─→ MPU6050、MAX30102、OLED SSD1306
            │
            └─→ 【单独一路 3.3V ≥300mA】──→ ESP01S 的 VCC
```

### 三条硬性要求

1. **ESP01S 必须独立供电，能力 ≥300mA。**  
   它在 Wi-Fi 发射瞬间的电流峰值远大于静态值。若与 MCU 共用一路或从开发板  
   的 3.3V 引脚取电，会出现"AT 指令偶尔无响应 / 反复重启 / 联网randomly 断"  
   —— 这是同类项目最常见的失败原因。VCC–GND 之间建议并 **100µF 电解 + 0.1µF 陶瓷**。
2. **所有 GND 必须共地。** 包括升压模块、ESP01S、各传感器、调试串口。  
   只接信号不接地是"设备没反应"的高频原因。
3. **VBAT 建议接纽扣电池（可选）。** 不接则掉电后 RTC 时间丢失，固件每次上电  
   都会用 `user_config.h` 里的 `RTC_INIT_*` 重新置初值。固件同时上报 `uptime_ms`，  
   上位机可据此判断时间戳可信度。

| 信号           | 位置           | 推荐阻值       | 说明                                         |
| ------------ | ------------ | ---------- | ------------------------------------------ |
| DHT11 DATA   | PA1 ↔ 3.3V   | 4.7K ~ 10K | 必需。多数 DHT11 **模块**已自带，裸传感器必须外接             |
| DS18B20 DQ   | PB12 ↔ 3.3V  | 4.7K       | **必需**。固件把 PB12 配成开漏输出，写 1 时引脚是高阻，全靠这个电阻拉高 |
| I2C1 SCL     | PB6 ↔ 3.3V   | 4.7K       | OLED / MAX30102 两个模块中**任意一个**带即可，不要每个都加（并联后阻值过低） |
| I2C1 SDA     | PB7 ↔ 3.3V   | 4.7K       | 同上                                         |
| **I2C2 SCL** | **PB10 ↔ 3.3V** | **4.7K**   | MPU6050 模块（GY-521 类）**通常板载自带**，不必再加。与 I2C1 是两条独立的线，**上拉不能共用** |
| ESP01S EN（= CH_PD） | EN ↔ 3.3V   | 10K **或直连** | **必须接高**，否则芯片停机、串口完全无响应              |
| ESP01S IO0 / IO2 | ——                 | **不需要**    | ESP-01S 板载已上拉，**悬空即可**；**切勿接 GND**（会进下载模式/卡死） |

> 建议仍保留外部 4.7K。

## 五、逐模块详细接线

### 5.1 MAX30102（心率 / 血氧）

| 模块引脚 | 接到                         |
| ---- | -------------------------- |
| VIN  | 3.3V                       |
| GND  | GND                        |
| SCL  | PB6                        |
| SDA  | PB7                        |
| INT  | **不接**（固件采用轮询 FIFO，未使用该引脚） |

地址 `0x57`（`user_config.h` 中 `MAX30102_I2C_ADDR7`）。  
模块通常自带 3.3V 稳压与 I2C 上拉。**血氧值未标定前固件不会输出估算值**  
（`SPO2_CAL_ENABLED = 0`，上报 0 且有效性标志为 0），只保留 R 值供标定。

### 5.2 MQ-2（烟雾 / 气体）

| 模块引脚 | 接到                 |
| ---- | ------------------ |
| VCC  | **5V**（加热丝额定电压）    |
| GND  | GND                |
| AO   | **PB1（经分压，见下方警告）** |
| DO   | 不接（固件不用数字阈值输出）     |

> ⚠️ **必须处理的风险：AO 超压**  
> MQ-2 的 AO 是负载电阻上的分压，**高浓度时输出可接近 VCC**。若 VCC = 5V，  
> AO 可能输出接近 5V，而 STM32 的 ADC 引脚上限是 `VDD + 0.3V ≈ 3.6V`。  
> **直接接入有损坏引脚的风险。** 二选一：
>
> - **方案 A（推荐）**：5V 供电，AO 经电阻分压后再接 PB1。  
>   例：`AO ──10K──┬── PB1`，`├──20K── GND`，则 5V → 3.33V。  
>   注意分压后满量程刻度变化，`GAS_ALARM_LEVEL` 的语义需重新核对。
> - **方案 B**：把模块 VCC 改接 3.3V。AO 自然不超过 3.3V，最安全，  
>   但加热丝电压不足、灵敏度下降（能否满足需求需实测）。
>
> 本固件的 `gas_level` 是 **"ADC 量程的相对百分数"**（`mq2.c`）：  
> `gas_level = ADC原始值 × 100 / 4095`。**不是 ppm，也不是 %LEL。**  
> 需求给的阈值 50 即"量程的 50%"。要换成 ppm 必须用标准气体标定后替换该函数。

### 5.3 DS18B20（温度）

| 模块引脚    | 接到   |
| ------- | ---- |
| VDD（红线） | 3.3V |
| DQ（黄线）  | PB12 |
| GND（黑线） | GND  |

DQ **必须**外接 4.7KΩ 上拉到 3.3V（防水探头三线制不含上拉电阻）。  
固件采用**两阶段读取**：`StartConvert()` 发命令后立即返回，1 秒后再取结果，  
避免 12 位转换的等待阻塞实时任务（`ds18b20.c` 头部说明）。

### 5.4 DHT11（温湿度）

| 模块引脚 | 接到              |
| ---- | --------------- |
| VCC  | **3.3V**（见下方说明） |
| DATA | PA1             |
| GND  | GND             |

- DATA 需 4.7K~10K 上拉到 3.3V（模块通常自带）。
- **务必用 3.3V 供电**：若用 5V 供电，DATA 输出高电平会接近 5V，超过 STM32 输入上限。
- 读取间隔 ≥1s，固件已设为 2s（`DHT11_PERIOD_MS`）。
- DHT11 失败时，固件用 DS18B20 的温度替代，并在 JSON 中标注 `temp_src`（容错机制）。

### 5.5 MPU6050（六轴姿态 / 加速度）

**默认接到 I2C2（独立总线）：**

| 模块引脚      | 接到       | 说明                             |
| --------- | -------- | ------------------------------ |
| VCC       | 3.3V     |                                |
| GND       | GND      |                                |
| SCL       | **PB10** | I2C2 SCL，独占一条总线，不与 OLED 并联     |
| SDA       | **PB11** | I2C2 SDA                       |
| **AD0**   | **GND**  | 决定地址为 `0x68`。接 3.3V 会变成 `0x69` |
| INT       | 不接       | 固件用 100ms 轮询读取                 |
| XDA / XCL | 不接       | 外部传感器接口，未使用                    |

> **若把 `MPU6050_ON_I2C2` 置 0**（回到共用总线），则 SCL 接 **PB6**、SDA 接 **PB7**，
> 与 OLED、MAX30102 并联 —— 线必须跟着改，否则姿态数据读不出来。
> 两种接法的对比、切换步骤与自检屏判读见 **`docs/19-姿态传感器换到I2C2.md`**。
>
> 地址判据仍是 `MPU6050_I2C_ADDR7 = 0x68`（AD0 接 GND），换总线不改地址。

> 固件强制使用 **±8g 量程**（`MPU6050_ACCEL_FS_G = 8`）。  
> 若按常见例程配成 ±2g，冲击信号会被量程**削顶在 2g**，需求里的  
> "加速度 > 2.5g"判据将**永远无法满足**——这是同类作品实测失败的典型原因。

### 5.8 蜂鸣器

固件按 **3 线蜂鸣器模块、低电平触发**配置（`BUZZER_ACTIVE_HIGH = 0`）。

**若是 3 线模块（VCC / GND / S）：**

| 模块引脚 | 接到          |
| ---- | ----------- |
| VCC  | 3.3V        |
| GND  | GND         |
| S    | **PB5**（信号） |

**若是 2 线裸蜂鸣器（+ / −）：**

| 蜂鸣器    | 接到   |
| ------ | ---- |
| +（正极）  | GND  |
| −（负极）  | PB5  |

> 2 线接法说明：低电平触发意味着**电流由 PB5 灌入**（PB5 输出低电平时形成回路），  
> 所以正极接 3.3V 侧、负极接 PB5。若接反（+ 接 PB5、− 接 GND），  
> 静音时 PB5 输出高电平，蜂鸣器会**一直响**。

**其它要点：**

- 极性由单个宏控制：`user_config.h` 的 `BUZZER_ACTIVE_HIGH`
  （`0` = 低电平响，`1` = 高电平响）。**改这一个宏即可**，`buzzer.c` 与
  `main.c` 的初始化静音、错误长鸣都已跟随该宏，无需改其它代码。
- 由于静音态是"输出高电平"，**建议在 S 脚与 3.3V 之间加一个 10K 上拉电阻**：
  上电到 `MX_GPIO_Init()` 执行前，PB5 处于复位后的浮空输入状态，  
  有上拉可确保这段时间不会因干扰误响。
- 若蜂鸣器电流超过约 20mA，**请用 NPN 三极管（如 S8050）或达林顿驱动**，  
  不要直接挂在 IO 上（STM32 单个 IO 的持续电流能力有限）。  
  经三极管驱动时极性可能反转，以实测为准（响 = 静音宏取反）。
- 若使用**无源蜂鸣器**，需要 PWM 驱动才能发声；`buzzer.c` 中的 `Buzzer_On()`  
  需改用 TIM 的 PWM 输出（本工程未启用 PWM）。

### 5.9 ESP01S（Wi-Fi）

> **丝印说明**：`CH_PD` 与 `EN` 是**同一根引脚**。老 ESP-01 丝印为 `CH_PD`
> （Chip Power Down），ESP-01S 及更新文档丝印为 `EN`（Enable）。
> 本工程按你模块的实际丝印（`EN`）书写，看到哪个都按同一根脚处理。

| 模块引脚      | 接到                 | 说明                            |
| --------- | ------------------ | ----------------------------- |
| VCC       | **独立 3.3V ≥300mA** | 切勿与 MCU 共用一路                  |
| GND       | GND                | 必须与 MCU 共地                    |
| TX        | **PA10**           | 模块 TX → STM32 的 USART1 RX     |
| RX        | **PA9**            | 模块 RX ← STM32 的 USART1 TX     |
| **EN**（= CH_PD） | **3.3V**          | **必须接高**，否则芯片处于停机态、完全无响应      |
| **IO0**（GPIO0） | **悬空不接**         | 启动模式选择脚，**绝对不能接 GND**          |
| **IO2**（GPIO2） | **悬空不接**         | 启动脚，**绝对不能接 GND**              |
| RST       | 3.3V（经 10K，可选）     | 低电平复位，不接也能工作                  |

#### IO0 / IO2 为什么不能接 GND（最常见的"AT 没反应"原因）

ESP8266 在上电后的最初几毫秒会采样 **IO0** 与 **IO2** 决定启动模式：

| IO0 状态 | IO2 状态 | 结果                    |
| ------ | ------ | --------------------- |
| 高 / 悬空 | 高 / 悬空 | **正常运行固件**（我们要的）      |
| **低**  | —      | 进入 **UART 下载模式**，AT 固件不跑 |
| —      | **低**  | 进入 SDIO 启动模式，芯片**卡死不启动** |

- 很多新手看到 `IO0` 就当成"使能脚"接到 GND —— 这会让模块进入烧录模式，
  表现就是**串口发 AT 完全没回复**，而电源、接线看起来都没问题。
- **ESP-01S 的 `S` 版本板上已自带上拉电阻**（IO0、IO2、RST 均有），
  所以正常情况**悬空即可**，不需要额外加电阻。
  老版 ESP-01 没有这些上拉，若用的是老版，需自行加 10K 上拉到 3.3V。
- 若 IO0/IO2 你接了别的器件（按键、继电器等），务必确认它**不会在复位期间把它拉低**。
  另外部分 ESP-01S 的板载蓝色 LED 接在 **IO2** 上且为**低电平点亮**，
  属正常现象，不影响功能。

#### 其它要点

- 通信参数 **115200-8N1**（若 AT 无应答，先试 9600）。
- **TX/RX 需要交叉**：模块 TX 接 MCU RX，模块 RX 接 MCU TX。
- ESP01S 是 3.3V 器件；STM32 也是 3.3V，直接相连即可，无需电平转换。
- ESP01S 引脚间距 **2mm**，需要专用转接板。
- **VCC 的电流余量要够**：Wi-Fi 发射瞬时峰值可达 300mA 以上，
  供电不足的表现是「AT 偶尔无响应 / 模块反复重启」，极易被误判为固件问题。
- 固件**不依赖 AT 固件是否支持 MQTT 扩展指令**，而是在 TCP Socket 上  
  自己拼 MQTT 3.1.1 报文（`mqtt_client.c`），兼容性更好。
- Wi-Fi 必须工作在 **2.4GHz**，ESP01S 不支持 5GHz。

### 5.10 SOS 按键

| 按键  | 接到      |
| --- | ------- |
| 一端  | **PA4** |
| 另一端 | **GND** |

固件配置为**上拉输入 + 下降沿触发**（`main.c:224`）：平时上拉拉高，  
按下接地产生下降沿 → 触发 EXTI4 → 在中断里直接投递最高优先级报警任务  
（`ALARM_SOS`），并唤醒 Wi-Fi 任务抢发 SOS 报文。中断内含 200ms 软件消抖。

> 注意：按键**不要**接 3.3V。若确实要接 3.3V，需把配置改成  
> `GPIO_PULLDOWN + GPIO_MODE_IT_RISING`。

### 5.11 调试串口（USART2）

| USB-TTL | 接到                         |
| ------- | -------------------------- |
| TX      | **PA3**（STM32 的 USART2 RX） |
| RX      | **PA2**（STM32 的 USART2 TX） |
| GND     | GND                        |

**115200-8N1**。固件每 10 秒在此打印各任务的栈水位  
（`APP_ReportStackUsage()`）以及联网过程日志，是排查问题的首选窗口。

## 八、上电前自查清单

接完线、烧录前，请逐条确认：

- [ ] ESP01S 由**独立** 3.3V（≥300mA）供电，且 VCC 处并了 100µF + 0.1µF 电容
- [ ] 所有模块与 MCU **共地**
- [ ] MQ-2 的 AO **已做分压**（或改用 3.3V 供电）
- [ ] DHT11 用 **3.3V** 供电，不是 5V
- [ ] DS18B20 的 DQ 有 **4.7K** 上拉到 3.3V
- [ ] ESP01S 的 **EN（= CH_PD）已接到 3.3V**（不接则芯片停机、串口无响应）
- [ ] ESP01S 的 **IO0 / IO2 保持悬空**（接 GND 会进下载模式或卡死）
- [ ] ESP01S 的 **TX/RX 与 MCU 交叉**连接（TX→PA10，RX→PA9）
- [ ] MPU6050 的 **AD0 接 GND**（地址 0x68）
- [ ] MPU6050 的 **SCL/SDA 与 `MPU6050_ON_I2C2` 的取值一致**：`=1` 时接 **PB10/PB11**，
      `=0` 时接 **PB6/PB7**（**最易漏的一条**：接一头不改另一头就是"姿态传感器读不到"）
- [ ] SOS 按键一端接 PA4、一端接 **GND**（不是 3.3V）
- [ ] 蜂鸣器按**低电平触发**接线（3 线模块 S→**PB5**），且 `BUZZER_ACTIVE_HIGH = 0`
- [ ] 调试串口接 **PA2/PA3**，波特率 115200
- [ ] Wi-Fi 是 **2.4GHz** 频段
- [ ] 已修改 `user_config.h` 中的 `WIFI_SSID` / `WIFI_PASSWORD` / `MQTT_BROKER_HOST`
