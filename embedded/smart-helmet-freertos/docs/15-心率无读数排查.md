# 15 - 心率无读数排查（"X:OK / MAX:OK" 但一直显示 `--`）

> 适用场景：上电自检屏显示 `X:OK`、`MAX30102 OK`，说明**器件已在 I2C 总线上、
> 地址和芯片 ID 都正确**，但运行界面第 2 行一直不是心率数字。
>
> 注意：**"器件在总线上" ≠ "能读出心率"**。前者只证明 I2C 通信通、芯片是 MAX30102；
> 后者还要求"LED 亮起来 → 光穿过手指 → 光电二极管收到足够的光 → 有搏动分量"。

---

## 一、先看屏幕，"无读数"其实是三种不同的情况

第 2 行现在会明确写出卡在哪一环：

| 第 2 行显示 | 含义 | 去哪查 |
|---|---|---|
| `SPO2:MAX30102 NG` | 器件不在 I2C 总线上 | 接线/供电/地址（见 docs/14） |
| `PPG warming up` | 器件在线，但**连样本都没有**（攒不够 100 个 ≈ 2 秒） | FIFO 读不到数据 → 见第三节 |
| `HR:-- SpO2:--` | 样本进来了，但**算不出心率** | 看第 6 行的 d/a → 见第二节 |
| `HR:75 SpO2:--` | 正常 | — |

**这三种在旧版固件里都显示 `HR:--`**，所以以前分不清是"没接上"还是"没信号"，
只能反复猜。

---

## 二、第 6 行的 `PPG d:... a:...` 怎么读（关键判据）

心率还没读出来时，第 6 行（原 `STATUS: normal` 的位置）会显示：

```
PPG d:58234 a:312
```

- **d** = `HR_GetIrDc()`，**红外通道的直流分量** —— 反映"手指挡住了多少光"。
  手指盖住时通常有几万；没盖住时只有环境光，约 0~几十。
- **a** = `HR_GetPeakAmp()`，**交流峰值幅度** —— 反映"脉搏波有多大"。
  有正常搏动时通常几百到几千。

### 判读表

| d | a | 结论 | 处理 |
|---|---|---|---|
| ≈ 0 | ≈ 0 | **压根没采到光** | LED 没亮 / 手指没盖住光学窗口 / 模块异常 → 见第三节 |
| 很大（几万） | ≈ 0 | **有光，但没有搏动分量** | 手指没对准光学窗口、按得太轻/太重、手在动 → 见第四节 |
| 正常 | 几百~几千 | 信号已有，只是算法还没锁定 | 手指保持不动，等 10 秒左右 |
| 正常 | 正常 | 但仍不出心率 | 把这一屏拍下来反馈（可能是算法参数问题） |

> 心率一旦读出有效值，第 6 行会**自动恢复**成 `STATUS: normal`，不需要手动关。
> 想一直看到它，把 `user_config.h` 的 `HR_PPG_DEBUG_LINE` 置 1（默认就是 1）。

---

## 三、`d ≈ 0`（或一直 `PPG warming up`）时的硬件检查顺序

**先做这一步：把手指拿开，看传感器表面有没有微弱的红光。**
MAX30102 在 SpO2 模式下红光和红外 LED 是**交替点亮**的，人眼能看见红光的那一下。

| 现象 | 原因 | 处理 |
|---|---|---|
| 看不见任何红光 | 模块没供电 / VIN 不是 3.3V / 模块坏 | 量 VIN 对 GND 电压；换模块 |
| 有红光但 d 还是 ≈0 | 光没被反射回来 | 手指**必须直接贴在光学窗口上**（两个小圆点那一面），不要隔着外壳/胶带/保护膜 |
| 红光很暗 | LED 电流偏低 | `user_config.h` 里 `PPG_LED_PA_RED` / `PPG_LED_PA_IR` 从 `0x24`(≈7.2mA) 调到 `0x4F`(≈16mA)；仍不行调到 `0x7F`(≈25mA)，注意别长时间超规格 |
| 一直 `PPG warming up` | 根本没读到 FIFO 样本 | I2C 通信是通的（不然不会有 `X:OK`），重点查"模块是否被反复复位/供电跌落"，以及是否与 OLED 抢总线超时 |

### 关于"手指怎么放"（绝大多数翻车都在这）

- 手指**正面**（指腹）压在**光学窗口那一面**，把两个小圆点完全盖住，
  不能只盖一半、也不能只碰到边缘。
- 压力**适中**：压太紧会把毛细血管压瘪 → 搏动消失（d 正常而 a≈0 正是这个特征）；
  太松则漏环境光。
- 手指**保持不动**，算法需要 4 秒窗口 + 至少 3 个心跳间隔才能出第一个数，
  加上预热，**总共约 10 秒**。
- 环境强光（阳光直射）会淹没有效信号，尽量避光。
- 有些模块出厂带一层**保护膜/玻璃纸**，需要撕掉。

## 四、`d` 正常但 `a ≈ 0` 时

说明光路是通的、ADC 在正常工作，只是**没有搏动分量**。按可能性排序：

1. **压力过大**：最常见的自制"压力式"接法。放松手指，让指腹自然贴合。
2. **手指没对准**：慢慢平移手指，同时盯着 `a` 的值，找到 `a` 最大的位置。
3. **手在抖**：轻微晃动就会把交流分量淹没。放在桌面上、另一只手扶住。
4. **LED 电流偏低**：见上表调 `PPG_LED_PA_*`。
5. **模块体质**：个别低价模块光路做得很差，`a` 只能到个位数 —— 换一个对比。

---

## 五、"无读数"和"云端无数据"是两条独立的线

这两件事**没有因果关系**，别互相牵连着查：

| | 链路 | 判断依据 |
|---|---|---|
| 无读数 | MAX30102 → I2C1 → MCU | 屏幕第 2 行 + 第 6 行 `d/a` |
| 云端无数据 | MCU → USART1 → ESP01S → 热点 → 巴法云 | 屏幕第 8 行 `NET: ...` |

也就是说：**心率读不出来，不影响把其它数据发上去**；反过来，数据发不上去，
心率照样能在屏上显示。所以两件事要分开定位，各自看各自的那一行。

云端那一侧的最新判据见 `docs/13-数据是否真的到了云端.md`：
第 8 行 `NET: OK p=x e=y`（e 同步增长 = 真的到了云端）；
`NET: p=x NO ECHO`（假成功）；`NET: retry Ns` / `NET: TCP fail` 等（卡在建链）。

---

## 六、快速自查

- [ ] 拿开手指后，传感器表面能看到微弱红光（LED 在工作）
- [ ] 手指指腹完全盖住光学窗口（两个小圆点），不是只碰到边缘
- [ ] 压力适中：既压紧又不发白
- [ ] 手指保持不动 ≥10 秒
- [ ] 避开直射强光
- [ ] 模块保护膜已撕掉
- [ ] 第 2 行不是 `SPO2:MAX30102 NG`（是的话转 docs/14）
- [ ] 第 6 行的 `d` 有几万（不是 0）
