# 智能工地安全帽边缘感知系统

基于 **FreeRTOS** 的多传感器融合实时监控平台 —— STM32F103C8T6 + HAL 库 + Keil MDK。

多传感器采集 → 边缘判定（摔倒 / 气体 / 温度 / 心率血氧）→ 本地 OLED 显示 + 蜂鸣器报警 → WiFi 经 MQTT 上传云端。

## 硬件组成（全部使用需求清单中的器件）

主控 STM32F103C8T6 · MAX30102 · MQ-2 · DS18B20 · DHT11 · MPU6050 ·
OLED 0.96"(SSD1306) · 蜂鸣器 · ESP01S · 3.7V 电池 + 5V→3.3V（电源为硬件设计，不在固件内）

> 注：PT0603 光敏电阻于 2026-09-22 随"光照功能整体删除"一并移除（见 `docs/39`），
> 现固件不再采集光照，也不再有光照门限与 `lux` 上报字段。

## 五个任务（优先级按需求指定）

| 任务 | 优先级 | 周期/触发 | 职责 |
|------|--------|-----------|------|
| Alarm_Task | **3** | 阻塞等报警队列 | 蜂鸣器断续报警 + OLED 状态，支持抢占 |
| Data_Processing_Task | 2 | 阻塞等采样队列 | 摔倒状态机、心率、阈值判断、温度容错降级 |
| Sensor_Task | 1 | **100ms** | 读 MPU6050/MAX30102/DHT11/DS18B20/MQ-2 |
| WiFi_Task | 1 | **10s** + SOS 信号量 | 组 JSON、MQTT 上报、失败重连与报警 |
| Display_Task | 0 | **500ms** | 刷新 OLED |

通信：2 条消息队列 + 2 个信号量 + 2 个互斥量（清单与内存占用见 docs/01）。
SOS 按键（PA4 / EXTI4）走中断 → 队列直投最高优先级任务，不经过采样链路。

## 快速上手

> **注意：Keil 工程已经配置并编译验证完成**（0 错误 0 警告，见
> `docs/05-工程集成与编译验证.md`）。也就是说 **不需要再跑一遍 CubeMX**——
> 直接打开 `MDK-ARM/smart-helmet-freertos.uvprojx` 即可编译。
> 下面第 1 步只在你想用 CubeMX 重新生成工程时才需要。

1. （仅重建工程时）读 **docs/02-CubeMX配置指南.md**，用 CubeMX 生成 Keil 工程。
   关键点：72MHz 时钟、TIM3 预分频 72-1、USART1 开中断、FreeRTOS heap 10KB，
   时基源要选 TIM2（SysTick 让给 FreeRTOS），**不要在 CubeMX 里创建任务**。
2. （仅重建工程时）把 `user/Src/*.c` 加进工程、`user/Inc` 加入头文件路径，
   并把 `user/Src/main.c` 作为唯一的主程序。
3. 改 `user/Inc/user_config.h`：WiFi 名称密码、MQTT Broker 地址、以及你需要
   标定的阈值。
4. 编译烧录，按 **docs/04-调试验收清单.md** 逐阶段验证。

## 三件必须知道的事（详见 docs/03）

1. **没有的硬件绝不假装有**：无风扇、无补光灯、无 GPS/北斗、无 FSR402、无校时源。
   相关功能均以 `HW_xxx_PRESENT = 0` 条件编译保留接入点，SOS 上报的坐标标注为
   `configured_fixed`（固定工点坐标，非实时定位）。
2. **未标定的量绝不编数字**：血氧在标定前上报 `null`（只输出可验证的 R 值），
   MQ-2 只输出"满量程相对百分数"而不是 ppm。
3. **MPU6050 量程必须 ≥ ±4g**：否则 2.5g 的摔倒判据会被量程削顶，永远无法触发。
   本工程默认 ±8g。

## 已实现 / 未实现（诚实边界）

**已实现**：摔倒撞击检测（严格按需求三条件的状态机）、气体超标报警、温度上下限
处理与 DHT11→DS18B20 容错降级、湿度上下限、心率计算、OLED 六行显示、
MQTT QoS0 周期上报、SOS 中断即报、断线重连与蜂鸣告警、报警去重与抢占、
**报警门限在线配置（小程序下发，含 cv 指纹回读确认；见 `docs/34`）**。

**未实现**：血氧换算（待标定）、风扇/补光灯控制（硬件缺失）、GPS 定位（硬件缺失）、
佩戴检测（需求声明不实现）、MQTT QoS1/2、TLS 加密、本地数据存储、低功耗管理、
门限掉电保存（刻意不做：擦 Flash 会停总线 20~40ms，打断 5ms 周期的撞击监视任务）。

> **门限在线配置**：温湿度 / 心率 / 血氧 / 气体五个量的门限可以在微信小程序的
> 「阈值设置」页里改并下发，设备下一轮（≤10 秒）生效；超过门限时蜂鸣器按新门限报警。
> 下行**复用上报那条链路**（小程序 → `apis.bemfa.com/va/sendMessage` →
> `<主题>/set` → 平台推给订阅了 `<主题>` 的设备），设备侧没有新增连接、订阅或主题。
> 细节、取舍与已知限制见 `docs/34`。
>
> **门限改完有两步**（2026-09-23，见 `docs/40`）：拖滑块只改界面，要点按钮才落本机。
> 小程序另有一个「仅存本机」按钮 —— **只写本机、一条请求都不发**，用来实现
> "只让小程序告警、不让板子响"。告警判据本来就在小程序侧（读本机存储的门限），
> 与设备门限完全独立，所以这件事**固件侧一行未改**。
