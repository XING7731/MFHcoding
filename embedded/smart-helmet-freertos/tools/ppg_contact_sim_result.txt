PPG 接触瞬态仿真 —— 贴手后 3 秒稳定期挡住了什么
==============================================================================
场景一: 上电时没有手指(只有环境光), 1.0 秒后手指放上, 真值 72 bpm,
        共观察 60 秒
波形  : 环境光 300 -> 手指直流 50000, 脉搏波峰值 600, 漂移 400, 噪声 8
手指盖住时 IR = 50000, 拿开时 = 300, 相差 167 倍 ——
        这就是「阶跃」的来头: 高通必须把这一跳当成交流才会有问题。

  old     = 09-16 版: 无接触判定
  anchor  = 接触确认后清算法+锚定直流(去抖 300ms 后生效)
  snap    = 再加直流阶跃吸附(不等确认, 当场生效)
  new     = 再加 3 秒稳定期门控(本次交付)

------------------------------------------------------------------------------
一、贴手瞬间发生了什么(「读数随机」的物理来源)
------------------------------------------------------------------------------
  真实脉搏波经带通后的峰值约 540。

  old     贴手后 600ms 内检出的峰: [36422]        amp_max=   36422  阈值=   14569
  anchor  贴手后 600ms 内检出的峰: [36422]        amp_max=   36422  阈值=   14569
  snap    贴手后 600ms 内检出的峰: 无              amp_max=     598  阈值=     239
  new     贴手后 600ms 内检出的峰: 无              amp_max=     598  阈值=     239

------------------------------------------------------------------------------
二、后果: 贴手后多久才出得了数
------------------------------------------------------------------------------
  old     首次发布: 贴手后  34160 ms, 值  71 bpm (偏差 -1)
  anchor  首次发布: 贴手后   3320 ms, 值  71 bpm (偏差 -1)
  snap    首次发布: 贴手后   3320 ms, 值  71 bpm (偏差 -1)
  new     首次发布: 贴手后   3320 ms, 值  71 bpm (偏差 -1)

------------------------------------------------------------------------------
三、稳定期门控(用户要求的那条)
------------------------------------------------------------------------------
  稳定期从「确认贴上」起算: 去抖 300 ms + 稳定 3000 ms = 贴手后 3300 ms 结束
  对照(snap, 不加门控): 算法在贴手后 3320 ms 就已给出有效值
  加门控(new):          贴手后 3320 ms 才对外发布
  ⇒ 门控的真实代价 = 0 ms; 门控期间算法内部算出有效值 0 次。
    在本例里代价几乎为零 —— 算法本来就要到那个时刻才攒够 3 拍 IBI。
    信号越弱这个代价越大, 但那时它挡住的东西也越多(见第六节)。

------------------------------------------------------------------------------
四、反复贴 / 拿: 上一次次测量的残余会不会混进这一次
------------------------------------------------------------------------------
  拿开手指后 800 ms(去抖)内仍会显示最后一个数, 之后立刻停 ——
  这是刻意的: 去抖太短的话, 手指稍微一挪就重启一次 3 秒稳定期。

------------------------------------------------------------------------------
五、测量中贴合/压力突变: 会不会读出假数
------------------------------------------------------------------------------
  做法: 手指一直在, 但在第 8 秒把直流从 50000 抬到 58000(按紧一点),
        模拟一次向上阶跃。对照 old 与 new 的读数。
  old     阶跃后 0~4s 的读数集合: [71]                   amp_max=913
          最大偏差 -1 bpm
  new     阶跃后 0~4s 的读数集合: [71]                   amp_max=907
          最大偏差 -1 bpm

------------------------------------------------------------------------------
六、弱信号(贴不紧 / 末梢循环差): 头 3 秒的数会不会跳
------------------------------------------------------------------------------
  做法: 脉搏波幅度 600 -> 150(交流/直流 从 1.20% 降到 0.30%), 噪声 8 -> 14。
  问题: 信号弱时算法要更久才攒够 3 拍, 而这段时间里它可能先锁上个错的。

  snap    稳定期[1000~4300ms]内发布: 无                | 稳定期后 3 秒内发布: [71]
  new     稳定期[1000~4300ms]内发布: 无                | 稳定期后 3 秒内发布: [71]

------------------------------------------------------------------------------
七、门控代价 vs 心率 —— 3 秒够不够, 会不会拖慢
------------------------------------------------------------------------------
  算法至少要「1 个锚点峰 + 3 拍 IBI」才出得了数; 心率越快这个时间越短,
  而门控固定 3 秒 —— 所以代价只会出现在【心率偏快】的时候,
  反过来说: 心率偏慢时 3 秒甚至还不够算法自己攒够拍数, 门控等于零代价。

  真值    snap 出数       new 出数        门控代价
   50 bpm 5160 ms        5160 ms           +0 ms
   72 bpm 3300 ms        3300 ms           +0 ms
   90 bpm 3140 ms        3280 ms         +140 ms
  110 bpm 2940 ms        3280 ms         +340 ms

  注: 门控固定 3300 ms(含去抖), 心率 50 时算法自己就要 5160 ms,
      所以门控在那时候是零代价的。

结论: 全部通过。

三层修法各自的作用(按见效顺序):
  1) 直流阶跃吸附 —— 从根上不让阶跃变成假峰。这是本轮最关键的一条,
     没有它, 贴手后会有长达几十秒的「黑窗」, 那正是「读数随机」的来源。
  2) 接触锚定 + 清算法 —— 清掉上一次次测量的残余拍库, 不让两次混在一起。
  3) 3 秒稳定期门控 —— 用户要求的那条。它不改变算法结果, 改变的是
     「什么时候让用户看到」: 把贴手瞬间那些必然存在、但还不可信的中间态
     挡在门外, 屏上用一句倒计时代替一个会变的数。
